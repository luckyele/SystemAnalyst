# 系统分析师｜项目管理与治理考点笔记

> 适用科目：综合知识（选择题，含计算题）+ **案例分析（主观题，治理类大题的稳定出题方向）** + 论文（素材与案例共享）
> 命题定位：本模块是**案例分析"问题诊断"类大题的固定来源**。题干常见形态：项目延期/超支/质量事故/变更失控/风险爆发，要求"指出项目管理中存在的问题并给出改进措施"。**挣值分析与关键路径是选择题必考计算题**。

---

## 一、项目管理基础框架

### 1.1 项目与运营

**项目**：为创造独特的产品、服务或成果而进行的**临时性**工作——**临时性 + 独特性 + 渐进明细**。
**运营**：持续重复、维持业务运转的日常活动。
**项目集 / 项目组合**：项目集 = 相互关联、协调管理以获收益的一组项目；项目组合 = 为实现战略目标而组合管理的项目集、项目与运营。

### 1.2 五大过程组 × 十大知识域

**五大过程组**：启动 → **计划** → 执行 → **监控**（贯穿全程）→ 收尾。

**十大知识域**：**整体、范围、进度、成本、质量、人力资源、沟通、风险、采购、干系人**。

> **监控过程组贯穿项目始终**，只在收尾时结束——选择题常考。

### 1.3 关键文件的层次（区分点，易混）

| 文件 | 作用 | 谁能改 |
|---|---|---|
| **项目章程** | 正式批准项目、授权项目经理动用资源 | 发起人或项目启动者（项目经理**无权**修改） |
| **项目管理计划** | 整合各子计划的总体方案，是执行的依据 | 经**变更控制**方可修改 |
| **范围说明书** | 定义项目范围、可交付成果、验收标准、除外责任 | 经变更控制 |
| **WBS / WBS 词典** | 以可交付成果为导向的层级分解 | 经变更控制 |

## 二、计算类考点（选择题必考，务必会算）

### 2.1 三点估算（PERT）

```
期望工期  Te = (乐观 O + 4 × 最可能 M + 悲观 P) / 6
标准差    σ  = (P - O) / 6
方差      V  = σ²
```

**正态分布置信区间**（项目总工期近似服从正态分布）：

| 区间 | 完成概率 |
|---|---|
| Te ± 1σ | **68.26%** |
| Te ± 2σ | **95.46%** |
| Te ± 3σ | **99.73%** |

> 项目总工期期望 = Σ各活动 Te；项目总标准差 = √(Σ各活动方差)。**关键路径上的活动方差求和**。

### 2.2 关键路径法（CPM）

| 概念 | 计算 |
|---|---|
| **ES / EF** | 最早开始 / 最早完成，沿正推（EF = ES + 工期） |
| **LS / LF** | 最迟开始 / 最迟完成，沿逆推（LS = LF - 工期） |
| **总浮动时间（总时差）** | **TF = LS - ES = LF - EF** |
| **自由浮动时间（自由时差）** | **FF = min(紧后活动 ES) - 本活动 EF** |
| **关键路径** | 网络图中**总浮动时间为 0（或最小）**的路径，**决定项目最短工期**，可能不止一条 |

**四种依赖关系**：**FS 完成-开始**（最常用）、SS 开始-开始、FF 完成-完成、SF 开始-完成（最少用）。可带**提前量（Lead）**与**滞后量（Lag）**。

**进度压缩两法（必考辨析）**：

| 方法 | 手段 | 效果 | 代价 |
|---|---|---|---|
| **赶工 Crashing** | 投入更多资源 / 加班 | 缩短关键路径工期 | **成本增加**（选成本斜率最小的活动优先赶工） |
| **快速跟进 Fast Tracking** | 将串行的活动**改为并行** | 缩短工期 | **增加风险与返工** |

### 2.3 挣值分析（EVA，计算题必考）

**三个基本参数**：

| 参数 | 含义 | 公式 |
|---|---|---|
| **PV**（BCWS） | 计划价值：截至某时点**计划应完成**工作的预算 | 计划工作量 × 预算单价 |
| **EV**（BCWP） | 挣值：截至某时点**实际完成**工作的预算 | 实际完成百分比 × BAC |
| **AC**（ACWP） | 实际成本：截至某时点实际发生的成本 | — |

**四个偏差与指数**：

| 指标 | 公式 | 判定 |
|---|---|---|
| **进度偏差 SV** | EV − PV | **> 0 进度提前**；< 0 落后 |
| **成本偏差 CV** | EV − AC | **> 0 成本节约**；< 0 超支 |
| **进度绩效指数 SPI** | EV / PV | **> 1 提前**；< 1 落后 |
| **成本绩效指数 CPI** | EV / AC | **> 1 节约**；< 1 超支 |

**完工估算 EAC（三种情形，必背）**：

| 情形 | 公式 | 适用 |
|---|---|---|
| 剩余工作按**原预算**完成（非典型偏差，偏差不再发生） | **EAC = AC + (BAC − EV)** | 偏差已纠正 |
| 剩余工作按**当前 CPI** 完成（**典型偏差，题干无说明时默认**） | **EAC = BAC / CPI** = AC + (BAC − EV)/CPI | 偏差持续存在 |
| 同时受**进度与成本**双重影响 | **EAC = AC + (BAC − EV) / (CPI × SPI)** | 要求考虑进度拖累 |

**其他推导**：

- **ETC**（完工尚需估算）= EAC − AC
- **VAC**（完工偏差）= BAC − EAC（**> 0 预计节余**）
- **TCPI**（完工尚需绩效指数）= (BAC − EV) / (BAC − AC)（按原预算完工所需达到的效率）
- **完工百分比** = EV / BAC

> **记忆口诀**：**"三个参数记 PV/EV/AC；偏差用减法，指数用除法；EV 永远在分子/被减数位置"**。

### 2.4 沟通渠道数

**沟通渠道 = n(n − 1) / 2**（n 为干系人数量，含项目经理）。
例：团队从 6 人增至 9 人，渠道数从 15 增至 36，增加 21 条。

## 三、范围与进度管理

### 3.1 WBS 分解原则

- **以可交付成果为导向**（不是以活动为导向）；
- **100% 原则**：下一层之和必须**完整覆盖**上一层的全部范围；
- **8/80 小时规则**（或两周规则）：单个工作包的工作量控制在合理粒度；
- **滚动式规划**：近期细化、远期粗放；
- 每个工作包应有唯一的责任人，且**WBS 之外的工作不在项目范围内**。

### 3.2 两个易混概念

| 概念 | 含义 |
|---|---|
| **范围蔓延（Scope Creep）** | 未经控制的、**客户驱动的**范围扩大（需求悄悄变多） |
| **镀金（Gold Plating）** | **项目团队主动**提供了超出范围的额外内容（"多做了好事"——但仍是问题） |
| **范围确认（Validate Scope）** | **客户/发起人正式验收**可交付成果（外部） |
| **质量控制（Control Quality）** | 检查可交付成果**是否符合质量标准**（内部） |

## 四、质量管理

### 4.1 质量 vs 等级

**等级**是"功能多少"的**设计意图**（高等级产品可以低质量）；**质量**是"满足要求的程度"。**低质量是问题，低等级不一定是问题**。

### 4.2 三大过程辨析（必考）

| 过程 | 定位 | 典型活动 |
|---|---|---|
| **质量规划（Plan Quality）** | 确定标准与如何达标 | 制定质量指标、检查表 |
| **质量保证 QA（Manage Quality）** | **面向过程**，审计质量要求和过程合规性 | **过程分析、质量审计、持续改进**（PDCA、六西格玛） |
| **质量控制 QC（Control Quality）** | **面向结果**，检查交付物是否合格并纠偏 | **测试、检查、统计抽样、缺陷修复** |

> 一句话：**QA 保证"过程做对了"，QC 保证"结果做对了"**。

### 4.3 质量成本（COQ）

| 类别 | 内容 |
|---|---|
| **预防成本** | 培训、过程改进、评审、质量规划 |
| **评估成本** | 测试、检查、评审会议、度量 |
| **内部失败成本** | 交付**前**发现的缺陷修复、返工、重测 |
| **外部失败成本** | 交付**后**：投诉处理、保修、召回、赔偿、声誉损失（**代价最大**） |

> 结论：**增加预防与评估投入，可显著降低失败成本**，这是质量投资的论证逻辑。

### 4.4 老七种质量工具（必考）

| 工具 | 用途 |
|---|---|
| **因果图（鱼骨图 / 石川图）** | 追溯问题**根本原因**（常从"人机料法环"展开） |
| **流程图** | 展示过程步骤，找瓶颈与冗余 |
| **核查表（检查表 / 计数表）** | 收集与统计缺陷数据 |
| **帕累托图** | 按发生频率排序的柱状图 + 累计曲线，**遵循 80/20 法则，优先解决少数关键原因** |
| **直方图** | 展示数据分布形态 |
| **控制图** | 判**过程是否稳定**：上下控制限为 **±3σ**；**连续 7 点落在中心线同侧视为失控（七点法则）**，另有连续 7 点单调上升/下降判异 |
| **散点图** | 判断两个变量是否相关 |

**新七工具**（了解即可）：亲和图、关联图、系统图、矩阵图、矩阵数据分析法、**PDPC 过程决策程序图**、箭条图/网络活动图。

### 4.5 软件质量模型

| 模型 | 构成 |
|---|---|
| **McCall** | 产品**运行**（正确性、可靠性、效率、完整性、可用性）、产品**修正**（可维护性、可测试性、灵活性）、产品**转移**（可移植性、可复用性、互连性） |
| **ISO/IEC 9126（GB/T 16260）** | **六大特性**：功能性、可靠性、**易用性**、**效率**、**可维护性**、**可移植性**（下分 27 个子特性） |
| **ISO/IEC 25010** | **八大特性**：功能适用性、性能效率、兼容性、易用性、可靠性、**安全性**、可维护性、可移植性（新增安全性与兼容性） |

### 4.6 CMMI 五级（必考排序）

1. **初始级**（混乱、依赖个人能力）
2. **已管理级**（项目级过程受控，有基本管理）
3. **已定义级**（组织级标准过程，制度化）
4. **量化管理级**（量化管理与度量，统计控制）
5. **优化级**（持续过程改进与革新）

> CMMI 有**阶段式**（整体评级）与**连续式**（按过程域评级）两种表示法。

## 五、风险管理（案例大题高频）

### 5.1 风险的定义与四要素

**风险**是**尚未发生**的、可能对目标产生**正面或负面**影响的不确定事件；已发生即成为**问题/缺陷**。
四要素：**风险事件、发生概率、影响（后果）、触发条件（征兆）**。

### 5.2 风险管理六过程

```
① 规划风险管理 → ② 风险识别 → ③ 定性风险分析 → ④ 定量风险分析
                 → ⑤ 规划风险应对 → ⑥ 监控风险
```

**风险识别方法**（选择题归类）：**德尔菲法**（专家匿名多轮，避免权威主导）、**头脑风暴**、**访谈**、**SWOT 分析**、**核对单（检查单，基于历史项目）**、**根本原因分析**、**假设分析**、**因果图/影响图**。

**定性分析**：**概率与影响矩阵**（概率 × 影响 = 风险等级），结合风险紧迫性、邻近性、可检测性，输出**风险登记册**并排序。

**定量分析**：**蒙特卡洛模拟**（模拟项目工期/成本的概率分布）、**敏感性分析**（找最敏感的变量，常用**龙卷风图**）、**决策树分析 / EMV 期望货币值**、影响图、PERT。

### 5.3 风险应对策略（必考配对）

**消极风险（威胁）**：

| 策略 | 含义 | 例子 |
|---|---|---|
| **规避 Avoid** | 改变计划彻底消除风险 | 砍掉高风险功能、改用成熟技术、延长工期 |
| **转移 Transfer** | 把风险责任与后果转给第三方（**不消除风险**） | **买保险、外包、签固定总价合同、保函** |
| **减轻 Mitigate** | 降低发生概率或影响 | 增加测试、冗余设计、原型验证、培训 |
| **接受 Accept** | 不主动行动；可**主动接受**（预留**应急储备**）或被动接受 | 小概率小影响风险 |

**积极风险（机会）**：**开拓 Exploit**（确保机会一定发生）、**分享 Share**（与第三方合作共担）、**提高 Enhance**（提高发生概率）、**接受 Accept**。

### 5.4 储备管理

- **应急储备**：应对**已识别**风险（"已知-未知"），**由项目经理直接支配**，计入成本基准；
- **管理储备**：应对**未识别**风险（"未知-未知"），**需高层审批**，**不计入成本基准**（但在项目总预算内）。

**风险监控手段**：**风险审计**、**储备分析**、**技术绩效测量**、**偏差与趋势分析**、**状态审查会**、**权变措施**（应对已发生的未知风险，属"救火"）。

## 六、配置管理（案例大题高频）

### 6.1 配置项与分类

**配置项（CI）**：处于配置管理之下的工作产品，包括**产品组成部分**（需求文档、设计文档、源代码、测试用例、数据字典、可执行程序）与**项目管理文档**（计划、进度、风险登记册）。
分为**基线配置项**（需求、设计、源代码等，需严格变更控制）与**非基线配置项**（各类计划、报告、会议记录）。

### 6.2 三级配置库（必考）

| 配置库 | 别名 | 用途 | 控制强度 |
|---|---|---|---|
| **开发库** | 动态库 / 程序员库 / 工作库 | 开发人员个人工作区，存放草稿 | 最弱，开发者自行控制 |
| **受控库** | 主库 / 系统库 | 存放**已通过评审的阶段性成果（基线）** | **强，变更须走流程** |
| **产品库** | 静态库 / 软件仓库 | 存放**已定型的最终产品**，等待交付 | 最强 |

**典型场景判定**：程序员发现已入库的受控库代码有 bug → **不能直接修改**，必须**提出变更申请 → 审批 → 从受控库检出 → 修改 → 评审 → 重新入库**。

### 6.3 版本号规则（选择题常考）

| 状态 | 版本号形式 | 说明 |
|---|---|---|
| **草稿态** | **0.YZ** | YZ 为 01～99，随草稿递增 |
| **正式发布态** | **X.Y** | X 主版本号 1～99；Y 次版本号 0～99；重大修改 X 递增，局部修改 Y 递增 |
| **正在修改态** | **X.YZ** | 在 X.Y 基础上追加修订号 Z，修改完成后去掉 Z 成为正式版 |

### 6.4 配置管理六活动

**配置项标识** → **配置控制**（变更控制） → **配置状态报告（状态说明）** → **配置审计** → **配置管理计划制定** → **配置库管理（发行与交付）**。

### 6.5 两种配置审计（必考辨析）

| 审计 | 关注 | 回答的问题 |
|---|---|---|
| **功能配置审计** | **验证配置项的实际功效是否与其需求一致**（做得对不对） | 功能是否符合需求规格？测试是否通过？ |
| **物理配置审计** | **验证配置项的物理存在性、完整性与一致性**（东西全不全） | 交付的版本是否完整？文档与代码是否一致？ |

### 6.6 角色

- **CMO（配置管理员）**：建立与维护配置库、标识配置项、生成配置状态报告、组织配置审计；
- **CCB（配置控制委员会）**：**审批**基线变更，决定变更是否批准及优先级；
- **配置经理**：配置管理负责人。

## 七、变更管理（案例大题高频）

### 7.1 变更分类

**按性质与影响范围**：重大变更（影响基线、范围、工期、成本）→ 由 **CCB 审批**；重要变更 → CCB 或指定负责人审批；一般变更 → 项目经理审批。
**按紧急程度**：常规变更、紧急变更（可先实施、事后补办审批手续，但必须留痕）。

### 7.2 变更控制七步（能默写）

```
① 提出与接受变更申请（书面化，记录来源、原因、内容）
② 变更评估（影响分析：范围 / 进度 / 成本 / 质量 / 风险 / 配置 / 合同）
③ CCB 审批（重大变更须 CCB，一般变更由项目经理）
④ 变更决策通知干系人（批准与否均须回执）
⑤ 实施变更（修改相关配置项与计划）
⑥ 验证变更（测试 + 评审，确认未引入新问题）
⑦ 配置更新与发布（更新基线、版本、配置状态报告，通知全体干系人）
```

**配套机制**：**变更日志**（记录每次变更的全过程与状态）、**变更控制委员会 CCB**、**配置管理系统**。

> **案例破题套路**：题干出现"口头提要求""直接改代码""改完没记录""后来发现需求漏做""版本混乱、无法回退"，一律从**变更流程缺失 + 基线未建立 + 配置库管理混乱 + 无变更日志 + CCB 缺位**五个角度切入。

## 八、干系人、沟通与团队

### 8.1 干系人管理

- **干系人识别** → **干系人分析**（权力/利益方格：重点管理、随时告知、令其满意、监督）→ **干系人参与计划** → 管理参与 → 监督参与；
- **权力高、利益高**的干系人 → **重点管理（密切管理）**；权力高利益低 → **令其满意**；权力低利益高 → **随时告知**；权力低利益低 → **监督（花最少的精力）**。

### 8.2 沟通方式

**推式**（邮件、报告，单向推送）、**拉式**（知识库、门户，按需自取）、**交互式**（会议、电话、即时通讯，**最有效**）。
**沟通障碍**：信息过载、过滤、选择性知觉、情绪、语言、文化、缺乏信任。
**沟通渠道数** = n(n−1)/2。

### 8.3 RACI 责任分配矩阵

**R 执行**（具体干活，可多人）、**A 负责/问责**（**唯一一人**，最终责任）、**C 需咨询**（双向沟通）、**I 需知情**（单向通知）。

### 8.4 团队建设五阶段

**形成 Forming**（相互试探、依赖领导）→ **震荡 Storming**（冲突爆发、意见分歧）→ **规范 Norming**（建立规则、开始协作）→ **成熟 Performing**（高效自治、绩效最高）→ **解散 Adjourning**（收尾、释放资源）。

### 8.5 冲突管理五策略（选择题常考排序）

**问题解决 / 协作（最佳，双赢，治本）** > **妥协 / 调和（各让一步，双输部分）** > **缓和 / 包容（求同存异，暂时）** > **撤退 / 回避（推迟）** > **强迫 / 命令（赢-输，最快但伤关系）**。

> 结论：**首选问题解决（协作）**；紧急情况下才用强迫。

### 8.6 激励理论（归类题）

| 理论 | 核心 |
|---|---|
| **马斯洛需求层次** | 生理 → 安全 → **社会（归属）** → **尊重** → **自我实现**（**低层满足后高层才起作用**） |
| **赫兹伯格双因素** | **保健因素**（薪资、工作条件、公司政策——**缺失则不满，具备也不激励**）vs **激励因素**（成就、认可、责任、成长——**才真正产生激励**） |
| **麦克格雷戈 X/Y 理论** | **X 理论**（人本懒惰、需强制）vs **Y 理论**（人本主动、自我管理） |
| **期望理论（弗鲁姆）** | 激励力 = **期望 × 工具性 × 效价** |
| **麦格雷戈/麦克莱兰成就理论** | 成就需要、权力需要、亲和需要 |

## 九、采购合同、招投标与法律法规

### 9.1 合同类型与风险归属（必考）

| 合同类型 | 缩写 | 风险归属 | 适用 |
|---|---|---|---|
| **固定总价（总价包干）** | **FFP** | **卖方风险最大**，买方最小 | **需求明确、范围稳定** |
| 总价加激励 | FPIF | 共担，有最高限价 | 范围较明确，有绩效目标 |
| 成本加固定费用 | CPFF | **买方风险最大** | 需求高度不确定、研发类 |
| 成本加激励费用 | CPIF | 共担 | — |
| 成本加奖励费用 | CPAF | 买方最大 | 主观评价 |
| **工料合同** | **T&M** | 共担 | 小额、短期、人员补充、紧急 |

> 记忆：**范围越不确定，风险越往买方（甲方）偏；范围越明确，越敢签固定总价。**

### 9.2 招投标要点

- **方式**：**公开招标**（发布公告，不限对象）与**邀请招标**（邀请不少于 **3 家**特定法人）；
- **流程**：招标公告 → 资格预审 → 发售招标文件 → 投标 → **开标**（截止时间内公开进行）→ **评标（评标委员会，专家不少于成员总数 2/3）** → 中标候选人公示 → **中标通知书** → **自通知书发出之日起 30 日内订立书面合同**；
- **中标条件**：**综合评分最高**，或满足条件下**经评审的投标价格最低**（但**不得低于成本**）；
- **废标（重新招标）情形**：投标人少于 3 个；有效投标不足 3 个且明显缺乏竞争；所有报价均超预算；出现影响采购公正的违法违规行为；
- **禁止行为**：串通投标、低于成本价竞标、以他人名义投标或弄虚作假、泄露标底。

### 9.3 知识产权（综合知识必考）

| 类型 | 取得方式 | 保护期 | 要点 |
|---|---|---|---|
| **著作权（版权）** | **自动产生**（完成即享有，登记仅作证据） | 自然人：**终生 + 死后 50 年**；法人/职务作品：**首次发表后 50 年** | **保护表达，不保护思想、算法、方法本身** |
| **专利权** | 须**申请授权** | **发明 20 年**、实用新型 10 年、外观设计 15 年（**均自申请日起算**） | 新颖性、创造性、实用性；**纯算法/数学方法不授专利，与技术结合形成技术方案的可授** |
| **商标权** | 须注册 | **10 年**，**可无限续展** | — |
| **商业秘密** | 无需申请 | **无固定期限**，取决于保密措施 | 需具备秘密性、价值性、保密性 |

**职务作品 / 职务开发**：**作者享有署名权**，其他著作权归单位；**职务发明创造**的专利申请权与专利权归单位。
**软件著作权**：登记机构为中国版权保护中心；**软件著作权保护期 50 年**（单位作品，自首次发表起算；未发表的自开发完成起 50 年）。

### 9.4 标准化基础

| 层级 | 代号 | 特性 |
|---|---|---|
| **国家标准** | **GB（强制性）、GB/T（推荐性）** | 强制性标准**必须执行**；推荐性标准**自愿采用**，但被法规引用或合同约定后**必须执行** |
| 行业标准 | 如 GA（公安）、JR（金融）、SJ（电子） | 无国标时制定，有国标后即行废止 |
| 地方标准 | DB | 限本区域 |
| 团体标准 / 企业标准 | T/xxx、Q/xxx | 企业标准需自我声明公开 |

**其他要点**：标准**复审周期一般不超过 5 年**；**国际标准**：ISO（国际标准化组织）、IEC（电工）、ITU（电信）；新版《标准化法》自 **2018-01-01** 施行。

## 十、考法拆解与得分逻辑

### 10.1 综合知识（选择题）

**考法 1｜挣值分析计算**
给出 PV / EV / AC，判断"进度是否提前、成本是否超支"，并计算 EAC。
解题顺序：**先判 SV/CV 正负 → 再算 SPI/CPI → 题干无特殊说明时按典型偏差 EAC = BAC / CPI**。

**考法 2｜关键路径与浮动时间**
给网络图，求关键路径长度、某活动的总浮动与自由浮动、压缩工期的措施选择（赶工 vs 快速跟进的**代价**）。

**考法 3｜过程辨析**
范围确认 vs 质量控制；QA vs QC；功能配置审计 vs 物理配置审计；应急储备 vs 管理储备；规避 vs 转移 vs 减轻。

**考法 4｜工具归类**
"找根本原因" → 因果图；"优先解决主要问题（80/20）" → 帕累托图；"判断过程是否稳定" → 控制图；"专家匿名多轮预测" → 德尔菲法；"量化工期概率分布" → 蒙特卡洛。

**考法 5｜合同与风险归属**
需求不明确 → 成本补偿类；需求明确 → 固定总价；小额短期 → 工料合同。

**考法 6｜知识产权与标准化年限**
著作权（终生+50 / 50）、专利（20/10/15，自申请日起）、商标（10 年可续展）、商业秘密（无固定期限）。

### 10.2 案例分析（主观题）

**通用作答结构（严格遵守）**：

> ① **引用题干事实**："题干中指出项目已延期 X 个月，期间客户多次口头提出新需求，开发人员直接修改代码且未更新设计文档……"
> ② **对应方法/原则**："这违反了变更控制流程与配置管理规范，属于典型的变更失控与基线缺失……"
> ③ **可执行动作**：分条给出机制性改进措施（制度 + 流程 + 工具 + 责任人）。

**常见诊断题的问题清单（逐条对照题干找）**：

| 症状 | 诊断 |
|---|---|
| 口头提需求、改完无记录 | **无变更控制流程、无变更日志** |
| 版本混乱、无法回退、线上与文档不符 | **配置管理缺失 / 配置库使用不规范 / 未做配置审计** |
| 需求越做越多、范围不断扩大 | **范围蔓延**，未做范围确认与基线管理 |
| 延期才发现、无预警 | **进度监控缺失**（无挣值分析、无里程碑评审、状态报告不透明） |
| 风险都变成了事故 | **风险识别与监控缺失**，无风险登记册、无应急储备 |
| 缺陷集中在上线后暴露 | **QA 与 QC 缺失**，测试介入过晚、无评审 |
| 干系人不满意、多头指挥 | **干系人识别与沟通管理缺失**，未明确 CCB 与决策机制 |

**答题增分项**：
- 措施要**机制化**，写清"**谁 + 何时 + 做什么 + 产出什么**"（如"由 CMO 每周五出具配置状态报告并发送给全体干系人"）；
- 涉及计算时**写出公式与代入过程**，即使结果有误也有步骤分；
- 改进措施给出**闭环**：制度建立 → 执行 → 检查（审计/评审）→ 持续改进。

**主要失分点**：
- 只罗列术语不结合题干事实；
- 只说"要加强管理"这类空洞表述，无具体动作；
- 计算题只写结果不写公式；
- 把"质量保证"与"质量控制"混用。

### 10.3 论文素材（项目管理方向）

- **背景段**：某 XX 系统建设项目，规模（投资额、工期、团队人数）、复杂度（多干系人、多供应商、技术新）；
- **难点段**：需求频繁变化、跨部门协调困难、工期紧、技术风险高、质量事故教训；
- **方案段**（按知识域成段，每段都要"措施 + 成效"）：
  1. **范围与变更管理**：建立 WBS 与范围基线 → CCB 与书面变更流程 → 影响分析模板 → 变更日志闭环；
  2. **进度与成本**：里程碑计划 + 关键路径识别 + **挣值分析月度跟踪（SPI/CPI 监控）** + 储备管理；
  3. **质量管理**：QA（过程审计、技术评审、编码规范）+ QC（分级测试、缺陷管理与趋势分析）+ 质量成本投入论证；
  4. **风险管理**：风险识别（头脑风暴 + 核对单 + 德尔菲）→ 概率影响矩阵排序 → 应对策略（规避/转移/减轻）→ 储备与**风险审计**；
  5. **配置与文档管理**：三级配置库 + 版本规范 + 基线管理 + 配置审计；
  6. **干系人与沟通**：权力利益方格分级管理 + 定期例会与状态报告 + RACI 明确责任；
- **结果段**：量化成效（如期交付、成本偏差控制在 X% 以内、缺陷密度下降 X%、客户满意度提升、通过验收）。

## 十一、五分钟自测

1. SV = EV − PV > 0 说明什么？（答案：**进度提前**）
2. EAC 在题干无说明（典型偏差）时用哪个公式？（答案：**EAC = BAC / CPI**）
3. 关键路径的定义？（答案：**总浮动时间为 0（最小）的路径**，决定最短工期）
4. 赶工与快速跟进的区别？（答案：赶工**加资源、增成本**；快速跟进**并行、增风险**）
5. QA 与 QC 的本质区别？（答案：**QA 管过程，QC 管结果**）
6. "连续 7 点落在中心线同侧"属于哪种工具的判异规则？（答案：**控制图**的七点法则）
7. 买保险、外包属于哪种风险应对策略？（答案：**转移**）
8. 管理储备是否计入成本基准？（答案：**不计入**，需高层审批）
9. 开发人员能否直接修改受控库中的代码？（答案：**不能**，须走变更流程）
10. 功能配置审计与物理配置审计的区别？（答案：**功效是否符合需求** vs **存在性与完整性**）
11. 需求不明确时应签哪类合同？（答案：**成本补偿类**（CPFF/CPIF），买方承担主要风险）
12. 专利保护期自何时起算？（答案：**自申请日起**算，发明 20 年）
13. 团队冲突解决的首选策略？（答案：**问题解决 / 协作**）
14. n(n−1)/2 是什么公式？（答案：**沟通渠道数**）
15. 应急储备由谁支配？（答案：**项目经理**直接支配，计入成本基准）

## 十二、速记口诀

- **三个参数 PV/EV/AC，偏差做减法、指数做除法，EV 恒在前**；
- **EAC 非典型 BAC−EV，典型除以 CPI，双压再除 SPI**；
- **关键路径零浮动，赶工花钱、快速跟进冒风险**；
- **QA 管过程、QC 管结果；预防评估省钱，内外失败烧钱**；
- **鱼骨找根因、帕累托抓关键、控制图看稳定**；
- **规避改计划、转移找别人、减轻降概率、接受留储备**；
- **开发库自己管、受控库走流程、产品库动不得**；
- **功能审计对不对，物理审计全不全**；
- **应急储备项目经理花，管理储备老板批**；
- **需求明确签总价，需求不明成本补**；
- **著作权自动有、专利要去申请、商标十年能续、商业秘密靠保密**。
