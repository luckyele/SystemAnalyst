## 一、报文认证（Message Authentication）

### 1.1 概念定位

**报文认证** = 验证收到的报文"**没被改过**"且"**确实来自声称的发送方**"，提供 **完整性 + 数据源认证** 两项服务。

**关键边界（高频陷阱）**：

- 认证 **不提供保密性**（报文通常仍以明文传输）；
- 认证 **不提供不可否认性**；
- 认证阻止 **主动攻击**（篡改、伪造、重放），加密才阻止 **被动攻击**（窃听）；
- 判错口诀：**"认证和加密都能阻止被动攻击"——错误说法**。

### 1.2 三类安全服务对照

| 安全服务 | 防什么攻击 | 典型技术 | 密钥形态 |
|---|---|---|---|
| 保密性 | 被动攻击（窃听） | AES / DES / 3DES / RC4 / SM4 | 对称或非对称 |
| 报文认证 | 主动攻击（篡改、伪造） | MD5 / SHA / SM3 / HMAC / CBC-MAC / CMAC | 摘要无密钥；MAC 需共享密钥 |
| 不可否认 | 事后抵赖 | RSA / DSA / ECDSA / SM2 数字签名 | 私钥签名、公钥验证 |

### 1.3 算法层次关系（理解主线）

```
散列函数（无密钥 → 仅防篡改）      MD5、SHA-1、SHA-2、SM3
        ↓ 引入共享密钥
报文认证码 MAC（防篡改 + 认证源）   HMAC、CBC-MAC、CMAC
        ↓ 换成非对称密钥对
数字签名（+ 不可否认）             RSA、DSA、ECDSA、SM2
```

> 数字签名内部就包含了"先摘要、后用私钥加密摘要"两个动作——**摘要技术是数字签名的基础组件**。

### 1.4 HMAC 运算结构（RFC 2104 / FIPS 198-1）

**公式**：`HMAC(K, M) = H( (K₀ ⊕ opad) ‖ H( (K₀ ⊕ ipad) ‖ M ) )`

**流程**：

```
                    ┌─ (K₀ ⊕ ipad) ‖ 报文 M ──→ H ──→ H1 ─┐
K ─→ 补 0 至 B 字节 ─→ K₀ ─┤                                      ├─ ‖ ──→ H ──→ MAC
                    └─ (K₀ ⊕ opad) ────────────────────────────┘
```

**要点拆解**：

1. **嵌套两次 Hash、密钥参与两次**：外层 Hash 掩盖内层中间结果，从而抵抗长度扩展攻击；
2. **为什么不能直接用 `H(K ‖ M)`**：MD5/SHA-1 等 Merkle–Damgård 结构存在**长度扩展攻击**，攻击者不知 K 也能追加数据造出合法 MAC；
3. `H(K ‖ M ‖ K)` 也不可靠（存在已知分析结论），唯有 HMAC 结构未被攻破；
4. **可插拔设计**：底层 Hash 可替换（MD5 → SHA-256 → SM3），这是 HMAC 的五大设计目标之一；
5. **ipad / opad**：`ipad = 0x36` 重复 B 次，`opad = 0x5C` 重复 B 次（记忆："外 5C 内 36"）；取值本身不决定安全性，只要求二者有足够大的汉明距离（至少一位不同）；
6. **密钥预处理**：K 短于 B 则右侧补 0；K 长于 B 则先做 `H(K)` 再补 0；B = 64 字节（MD5 / SHA-1 / SHA-256）；
7. **输出长度 = 底层 Hash 摘要长度**，允许截断（取最左 λ 位）。

### 1.5 其他 MAC 实现

- **CBC-MAC**：基于分组密码（DES/AES/SM4），取 CBC 模式最后一个密文分组作 MAC。注意 **不能与加密共用同一密钥**，且变长消息场景不安全；
- **CMAC / OMAC**：CBC-MAC 的安全改进版，支持变长消息；
- **GMAC**：GCM 认证加密模式中的认证部分，属于 **AEAD（认证加密）**。

### 1.6 必背数字

| 算法 | 输出长度 | 分组长度 B |
|---|---|---|
| MD5 | 128 bit | 512 bit（64 字节） |
| SHA-1 | 160 bit | 512 bit |
| SHA-256 | 256 bit | 512 bit |
| SHA-512 | 512 bit | 1024 bit |
| **SM3（国密杂凑）** | **256 bit** | 512 bit |
| HMAC-X | 同 X 的摘要长度 | 同底层 Hash |

## 二、MD 系列：MD7 不存在

### 2.1 家族谱系

| 算法 | 年份 | 输出 | 安全状态 |
|---|---|---|---|
| MD2 | 1989 | 128 bit | 已废弃 |
| MD4 | 1990 | 128 bit | 1995 年被 Dobbertin 攻破，废弃 |
| **MD5** | 1992 | **128 bit** | **2004 年王小云破解碰撞；2008 年据此伪造 X.509 证书；严禁用于安全目的** |
| MD6 | 2008 | 可变（0 < d ≤ 512 bit） | Merkle 树结构、可并行；Rivest 团队提交 NIST SHA-3 竞赛，2009 年因速度不达标 + 缺少抗差分攻击证明主动退出，未进第二轮，**从未标准化** |
| **MD7** | — | — | **不存在，纯干扰项** |

### 2.2 MD5 的考试定位

- 三个绑定数字：**128 位输出、512 位分组、已被攻破**；
- 可用场景：非对抗性校验（文件去重、缓存键、下载站校验码，前提是摘要值由可信渠道发布）；
- **禁用场景**：口令存储、数字签名、数字证书、MAC —— 见到即判错。

### 2.3 SHA / MD5 / SM3 安全现状速判

| 算法 | 输出 | 状态 |
|---|---|---|
| SHA-0 | 160 bit | ❌ 发布即有缺陷，废弃 |
| SHA-1 | 160 bit | ❌ 2017 年 SHAttered 碰撞，全面弃用 |
| SHA-256 / SHA-384 / SHA-512 | 256/384/512 bit | ✅ 当前工业界事实标准 |
| SHA-3（Keccak） | 224/256/384/512 bit | ✅ 海绵结构，作为 SHA-2 的备份方案 |
| SM3 | 256 bit | ✅ 国密标准（GB/T 32905-2016），未发现有效实际攻击 |

> **选择题优选顺序**：只要选项里有 SHA-256 / SHA-2 / SM3，就比 MD5、SHA-1 更优。

## 三、国密算法全家福（必背配对表）

| 算法 | 类型 | 参数 | 公开性 | 典型场景 | 记忆锚点 |
|---|---|---|---|---|---|
| **SM1** | 对称分组 | 128 bit | ❌ 未公开（IP 核） | 智能 IC 卡、安全芯片、加密卡、加密机 | 芯片里，软件调不了 |
| **SM2** | 非对称（ECC） | 256 bit | ✅ 公开（2010） | **数字签名、密钥交换、公钥加密** | 对标 RSA / ECDSA |
| **SM3** | 杂凑 / 摘要 | 256 bit | ✅ 公开（2010） | **报文摘要、HMAC-SM3** | 对标 SHA-256 |
| **SM4** | 对称分组 | 128 bit，32 轮非线性迭代 | ✅ 公开（2012） | 无线局域网 WAPI、数据传输与存储加密 | 对标 AES-128 |
| **SM7** | 对称分组 | 128 bit | ❌ 未公开（IP 核） | **非接触式 IC 卡：门禁卡 / 工作证 / 参赛证、赛事展会门票、校园与公交一卡通** | **门禁、一卡通、门票** |
| **SM9** | 标识密码 IBC（双线性对） | — | ✅ 公开（2016） | 免证书的标识加密与签名、IoT 认证、邮件加密 | 公钥即身份，省掉 CA |
| **ZUC**（祖冲之） | 序列密码 | 128 bit | ✅ 公开（2012） | 4G / 5G 空口加密（3GPP 128-EEA3 / EIA3） | 移动通信 |
| SSF33 | 对称分组 | 128 bit | ❌ 未公开 | 早期金融 IC 卡，已逐步淘汰 | 旧系统存量 |

### 3.1 三条记忆线

1. **不公开的只有 SM1 和 SM7**（"1 和 7 都锁在芯片里"），SM2 / SM3 / SM4 / SM9 / ZUC 均已发布为国家标准（GM/T 系列、GB/T 系列）；
2. **非对称只有 SM2 和 SM9**，其余全是分组/序列对称算法；
3. **摘要只有 SM3**，输出固定 256 bit。

### 3.2 选型决策速查

```
需要密码服务
├─ 要防抵赖 / 可仲裁（合同、交易、招投标） → SM2 数字签名（配 CA 证书）
├─ 只验完整性 / 做摘要               → SM3（或 HMAC-SM3 需认证源）
├─ 大数据量加密，软件实现             → SM4（GCM/CTR 模式）
├─ 免证书、海量 IoT 设备身份认证      → SM9（标识密码）
├─ 非接触式 IC 卡 / 门禁 / 一卡通     → SM7（专用芯片）
├─ 智能卡、加密机、密码卡             → SM1（专用芯片）
└─ 4G/5G 空口                       → ZUC
```

## 四、考法拆解与得分逻辑

### 4.1 综合知识（选择题）四大考法

**考法 1｜算法归类**

题干："下列不属于报文认证算法的是（ ）"，选项混入 **RC4 / AES / DES**。

- 判别口诀：**MD / SHA / SM3 = 摘要类；带 MAC / HMAC = 认证码类；DES / AES / RC4 / SM4 = 加密类；RSA / ECC / SM2 = 签名与加密类**；
- 注意：对称加密算法本身 **不是** 认证算法，但 CBC-MAC/CMAC 是"用分组密码构造的认证码"，两者别混。

**考法 2｜功能边界辨析（最高频）**

- 生成报文摘要的目的是 **防止篡改**；
- 用 **发送方私钥对摘要加密** 的目的是 **防止抵赖**；
- 二者合起来 = 数字签名；
- "先摘要后签名"的原因：**非对称算法速度慢 + 直接加密长报文存在安全隐患**；
- **MAC 不能防抵赖**（双方共享同一密钥，接收方自己也能生成合法 MAC，无法向第三方举证）——这是区分 MAC 与签名的唯一判据。

**考法 3｜场景选型**

| 场景 | 选型 |
|---|---|
| 下载文件校验、防误传 | MD5 / SHA-256（官方渠道发布摘要值） |
| 通信双方、API 调用，量大、要高吞吐、只需完整性 + 来源可信 | **HMAC** |
| 电子合同、招投标、金融交易（要防抵赖、可仲裁） | **数字签名 RSA / SM2** + CA 证书 |
| 既要保密又要认证 | 加密 + MAC，或直接用 **AES-GCM 等 AEAD 模式** |

**考法 4｜细节记忆**

- ipad = **0x36**、opad = **0x5C**；
- 密钥短于 B 补 0，长于 B 先 Hash；
- SM2 = 256 bit（**不是 128**）；SM3 = 256 bit；SM4 / SM7 = 128 bit；
- MD5 = 128 bit、SHA-1 = 160 bit、SHA-256 = 256 bit。

**考法 5｜干扰项识别（送分题，别丢）**

命题人常"顺着编号往下编"：**MD7、SM5、SM6、SM8、SM10 均不存在**。看到陌生编号，先怀疑它是否存在。

### 4.2 案例分析（主观题）答题模板

**典型题干**：某系统需进行信创国产化改造 / 满足等保三级要求 / 保障跨部门数据传输安全，请给出密码应用方案。

**作答结构（严格遵循，否则失分）**：

> ① **引用题干事实**："题干中系统是 XX 业务，存在跨网络传输、需留存操作凭证、涉及 XX 敏感数据……"
> ② **对应原则**：依据"机密性、完整性、可用性、不可否认性"四要素逐项分析；
> ③ **提出可执行动作**：给出算法组合 + 部署位置 + 管理机制。

**标准答法（三件套）**：

| 安全需求 | 技术措施 | 算法 |
|---|---|---|
| 身份鉴别 / 防抵赖 | 数字签名 + CA 证书体系 | **SM2** |
| 数据完整性 | 报文摘要 / HMAC | **SM3 / HMAC-SM3** |
| 数据机密性（传输 + 存储） | 对称加密（传输用 TLS 国密套件，存储用库内加密） | **SM4** |
| 密钥管理 | 密钥管理系统 KMS + 硬件加密机，密钥分级、定期更换 | — |

**专业加分点（拉开分差的关键）**：

- 明确指出 **SM1 与 SM7 算法未公开、无软件实现、无法接受第三方安全审计**，因此 **新建系统不采用**，仅在存量专用硬件（金融 IC 卡、门禁一卡通）中保留；
- 提到 **算法合规性**：选用国家密码管理局认可的商用密码算法与产品，不使用自研/未公开算法；
- 提到 **密钥全生命周期管理**（生成、存储、分发、更新、销毁）与 **硬件加密机**；
- 提到 **国密 TLS（GM/T 0024 双证书体系）**：签名证书 + 加密证书分离。

**主要失分点**：脱离题干泛泛罗列算法；只写技术不写管理；把 SM1/SM7 写进软件系统方案；把"完整性"和"不可否认"混为一谈。

### 4.3 论文素材沉淀

可复用的"背景—难点—方案—结果"模块：

- **难点段**：系统涉及跨部门数据交换，面临传输窃听、报文篡改、操作抵赖三类风险，且需满足信创与等保合规要求；
- **方案段**：建立以 SM2/SM3/SM4 为核心的密码应用体系——SM2 双证书实现身份认证与操作抗抵赖，SM3 实现关键报文与日志的完整性校验，SM4 实现敏感字段存储加密与传输信道加密，密钥统一由 KMS 管理并存放于硬件加密机；
- **结果段**：通过密评（商用密码应用安全性评估）／等保测评，操作行为可追溯，未发生数据泄露与篡改事件。

## 五、五分钟自测

1. HMAC 中 ipad 与 opad 的十六进制取值分别是多少？（答案：0x36、0x5C）
2. MAC 能否提供不可否认性？（答案：不能，共享密钥导致无法向第三方举证）
3. MD7 是什么？（答案：不存在，干扰项）
4. 国密体系中哪两个算法未公开？（答案：SM1、SM7）
5. 门禁卡、校园一卡通应采用哪个算法？（答案：SM7）
6. SM2 / SM3 / SM4 的密钥或输出长度分别是多少？（答案：256 / 256 / 128 bit）
7. 数字签名中"先摘要后签名"的两个理由是什么？（答案：非对称算法效率低；直接加密长报文有安全隐患）
8. 认证技术能否阻止窃听？（答案：不能，加密才行）

## 六、速记口诀

- **外 5C 内 36，HMAC 嵌套两遍 Hash**；
- **MD5 一百二十八，二〇〇四王小云**；
- **1 和 7 锁在芯片里，2 签名、3 摘要、4 加密、9 免证书**；
- **摘要防篡改、签名防抵赖、加密防窃听**；
- **陌生编号先怀疑：MD7、SM5、SM6、SM8 都是假的**。
