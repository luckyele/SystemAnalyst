# 第23章 AI智能体分析与设计核心知识点

## 一、近三年真题考情回顾

- **2024年两场**：AI 相关内容主要作为“信息化（含新技术）”方向的选择题出现（机器学习基本概念、智能算法应用），案例分析与论文均未以 AI 为独立主题命题，属于铺垫期。
- **2025年下半年**：案例必答题为需求工程，选答题覆盖结构化分析与设计、缓存数据库、嵌入式、Web 系统设计；论文四题分别为软件测试、设计模式应用、系统成本效益分析、云计算运维。AI 仍未单独命题，但已作为业务背景与工具词持续渗透（智能运维、智能客服等场景）。
- **2026年上半年（关键转折）**：
  - 案例分析第五题（选做）考“**Web 应用与 AI 智能体融合平台**”，三问依次为：后端架构选型对比（微服务架构与一体化快速架构）、面向 AI 智能体场景的负载均衡技术及其优缺点、平台常用中间件类别与典型产品。
  - 同场案例还考 Redis 缓存与分布式分片，命题特点分析明确把“AI 智能体架构”列为当年的前沿技术考点。
  - 论文第一题考“LLM 大模型语言辅助测试”：LLM 在生成测试用例过程中的具体实现、使用 LLM 的优势与问题及应对措施、其局限性与解决办法；另外三题分别为软件架构风格（种类举例与项目选型）、需求评审（走查/评审/检查三种形式及开发阶段应用）、安全架构（密码技术、权限控制、容灾与业务连续性）。
- **考纲变化**：有培训与模拟题资料反映，2026 版考纲在架构风格方向新增“智能代理（Agent）驱动架构”，其核心逻辑为“感知环境→推理决策→工具调用→结果反馈”闭环，大模型充当认知中枢，通过工具调用层与外部系统交互，区别于流程硬编码的传统架构。若属实，意味着 AI 智能体从“新技术背景”升级为“可设计、可选型的架构风格”。
- **趋势判断**：AI 考点的重心已从“大模型技术识别”（会不会）走向“智能体系统分析与设计”（怎么设计、怎么选型、怎么管住），命题形态以链路还原、架构选型、方案列举为主。

## 二、本章核心知识点

### 1. 智能体的定义与边界

- **定义**：具备环境感知、自主规划、工具调用、行动执行与反思能力的智能实体。在大模型语境下，智能体可归纳为“大模型中枢 + 规划 + 记忆 + 工具 + 编排 + 护栏”六件套。
- **与聊天机器人的区别**：聊天机器人是“输入→输出”的单轮问答；智能体是目标驱动、多步执行、带状态、能产生真实副作用（写库、发消息、调接口），且过程可观测、可干预。
- **智能体 vs 工作流（案例高频辨析）**：工作流路径预先定义、确定性强、可预测；智能体路径运行时决定，能在执行中反思并动态重规划。**反思与动态重规划是智能体与工作流的分水岭**。
- **智能体 vs CPS**：CPS 的闭环在物理世界（状态感知→实时分析→科学决策→精准执行）；智能体的闭环在数字世界（意图感知→规划推理→工具执行→结果反馈）。两者共享“感知-决策-执行”范式，但对象与实时性要求不同。

### 2. 运行主轴与体系架构

- **四段主轴**：感知（理解用户意图与环境状态）→ 规划（任务分解、思维链、子目标排序）→ 行动（工具调用产生外部操作）→ 反思（对执行结果自评估，决定继续、重试还是重规划）。
- **核心架构元素**：
  - 大模型中枢：承担语义理解与推理，是唯一的决策入口，但不直接访问外部世界。
  - 规划模块：把复杂任务分解为可执行子步骤，代表技术有任务分解、思维链（CoT）、ReAct（思考-行动-观察）循环。
  - 记忆系统：保存会话状态与跨会话知识。
  - 工具集：把外部系统能力以可调用接口暴露给智能体。
  - 编排器：调度多智能体或多步骤的执行顺序、分支与并发。
  - 护栏与评测：约束行为边界并度量效果。
- **记忆主线**：**感知定意图，规划拆步骤，行动调工具，反思做纠偏**。案例“流程还原题”基本按这四段出题。

### 3. 记忆机制与上下文工程

- **短期记忆**：保存当前会话的上下文，受上下文窗口（token 上限）约束，常规手段为滑动窗口、摘要压缩、KV 缓存复用前缀。
- **长期记忆**：跨会话保存用户偏好、历史结论与领域知识，落地形态为向量库、知识图谱、关系型档案库，靠存储介质与生命周期策略区分。
- **上下文窗口机制**：决定模型单次可处理的 token 长度与上下文组织方式，是大模型核心机制之一（与 Transformer 架构、向量嵌入、KV 缓存、RAG 并列）。
- **长上下文三种策略**：检索式（按需召回相关内容）、压缩式（摘要与信息抽取）、缓存式（KV 缓存避免重复计算）。策略选择取决于成本与准确率的权衡。

### 4. 工具调用与外部系统集成

- **本质**：Function Calling / Tool Use 是“模型输出结构化调用意图（工具名 + 参数）”，由执行层真正发起调用，模型本身不直接访问外部系统。**调用意图**与**实际执行**必须分开理解，这是命题点。
- **三段式链路**：模型生成调用意图 → 参数校验、鉴权与权限判定 → 真实执行并把结果回填为新一轮上下文。
- **工具集工程化要点**：工具注册与语义化描述、参数 schema、工具权限最小化、超时重试与幂等、返回结果裁剪（防止上下文膨胀）、工具调用审计日志。
- **MCP（Model Context Protocol）**：把工具与上下文接入标准化的开放协议，可作为工具生态演进的新技术补充识记。

### 5. 检索增强生成（RAG）全流程

- **七步主线**：文档加载 → 分块 → 向量化 → 向量库存放 → 检索召回 → 重排序 → 提示组装生成与引用溯源。
- **关键细节**：分块按语义边界切分而非定长切分；向量库用近似最近邻做语义匹配，专治关键词搜不到同义表达；**粗召回出候选集、重排序做精排**，二者的分工是准确率关键；引用溯源让结论回指原文出处，是抑制幻觉的首要手段。
- **三种知识注入路径辨析（高频）**：提示工程解决“怎么问”，RAG 解决“喂什么”，微调用领域数据更新权重、解决“模型会什么”。三者可组合使用，题干问“属于哪一路径”时按此对号入座。
- **幻觉**：生成内容看似合理却与事实不符。成因是模型以统计概率续写而非查证。抑制手段：引用溯源、检索置信度阈值、无法溯源即拒答、关键结论人工复核、评测集回归监控。
- **推理加速**：KV 缓存复用历史 Key/Value 避免重复计算；token 计数管控用于控制生成长度与成本。

### 6. 多智能体协作与编排

- **三种编排策略**：顺序式（流水线，前一环输出为下一环输入）、路由式（按意图分类分发到专职智能体）、层级式（管理者智能体拆解任务并调度执行者）。
- **通信模式**：共享黑板（共享上下文池）、消息传递（智能体间显式对话）、层次式（上行汇报、下行派发）。
- **该不该上多智能体**：任务可清晰分工、子任务需要不同专长或不同权限、数据可隔离时用；任务可线性完成时用单智能体，避免成本与不可控性。
- **风险**：误差逐级放大、通信开销高、并发冲突、责任归属不清（出问题时说不清是哪个智能体的责任）。

### 7. 智能体驱动的架构风格与参考架构

- **闭环逻辑**：感知环境 → 推理决策 → 工具调用 → 结果反馈。大模型是认知中枢，工具调用层负责与外部系统交互，执行路径由模型在运行时动态生成，而非流程硬编码。
- **与传统架构风格的对比**：事件驱动强调“消息解耦”，微服务强调“服务自治”，数据流与管道过滤器强调“固定处理链”，黑板风格强调“共享数据区协同”，Agent 风格的差异点是**路径动态性与目标驱动**。
- **参考架构分层**（案例画图与论文落点均可套用）：
  - 接入层：多终端接入、身份认证、敏感信息脱敏。
  - 网关层：统一路由、限流、熔断降级、灰度。
  - 编排层：规划、路由、多智能体协同、任务队列。
  - 模型与工具层：推理服务、向量数据库、工具网关、MCP 接入、外部系统 API。
  - 治理层：护栏、评测体系、日志审计、链路追踪、成本核算。
- **部署形态选型**：公有云大模型 API（上线快、能力强，但数据出域且调用成本随量线性上涨）对比私有化部署开源模型（数据不出域、成本可控、可做领域微调，但门槛高、算力投入大）。敏感行业与数据不出域要求高的场景优先私有化。

### 8. 工程化护栏、安全与评测

- **输入侧**：提示注入防护、敏感信息脱敏与清洗、越权意图识别、输入格式校验。
- **输出侧**：内容安全审核、格式与结构校验、敏感结论强制人工复核、引用溯源与结论可解释。
- **执行侧**：工具权限最小化、调用白名单、高风险动作加审批闸门（human-in-the-loop）、沙箱执行、幂等与回滚。
- **评测体系**：建设覆盖高频场景的评测集（黄金集），每次调整提示词、升级模型、变更知识库都跑回归测试；核心指标为任务成功率、问答准确率、检索召回率、幻觉率、工具调用成功率、单任务成本；指标回退即阻断发布。
- **合规底线**：数据不出域、模型备案与内容标识、调用日志留痕可审计、密钥集中管理。

### 9. 平台技术栈与中间件选型

- **中间件十类**：反向代理与负载均衡与 API 网关、消息队列、缓存、注册与配置中心、RPC 框架、向量数据库与检索引擎、容器编排与调度、任务调度与工作流引擎、日志监控与链路追踪、认证授权与密钥管理。
- **负载均衡在智能体场景的特殊性**：DNS 轮询（简单但粒度粗）、四层（吞吐高时延低但不解析内容）、七层（可按 URL/Header 路由并支持灰度限流）、推理感知调度（按队列长度、显存、token 负载分发，提升 GPU 利用率并支持流式输出）、一致性哈希（会话与上下文粘性）。算法层面最少连接与最短响应时间更适合推理这类长耗时、负载不均的请求。
- **向量数据库选型指标**：向量维度支持、召回率与 QPS、元数据过滤能力、是否支持混合检索、水平扩展与运维成本。典型产品为 Milvus、Qdrant、Chroma、Elasticsearch、PGVector。
- **消息队列与缓存不可混淆**：消息队列管异步解耦、削峰填谷与智能体间通信；缓存管快速读取、会话与上下文存储。

### 10. 智能体系统的需求分析与建模

- **需求分析要点**：把需求从“功能清单”升级为“任务与人机协作需求”，识别智能体能力边界、哪些环节可自动化、哪些必须人工兜底、在哪几个节点设置人工审核。
- **非功能指标**：幻觉率上限、响应时延（P95）、任务成功率、工具调用成功率、并发与吞吐、单位任务 token 成本、可解释与可审计性。
- **用例与建模**：智能体用例以“完成一项任务”为粒度而非“查询一条数据”，配套会话状态图与异常降级路径；跨系统协作部分沿用微服务与 Web 应用的既有分析模型。
- **运行与部署**：推理服务的弹性伸缩与量化部署、常见问答缓存、限流降级、灰度发布与回滚、容量按峰值任务量而非请求数估算。

### 11. 易混概念辨析汇总

| 概念对               | 判据（一句话区分）                                |
| ----------------- | ---------------------------------------- |
| 智能体 vs 工作流        | 工作流路径预定义，智能体路径运行时决定并可反思重规划               |
| 提示工程 vs RAG vs 微调 | 怎么问 / 喂什么 / 模型会什么                        |
| 智能体 vs 规则引擎/专家系统  | 前者由大模型基于概率推理，输出不确定且需护栏；后者基于确定性规则，输出可精确复现 |
| 智能体 vs RPA        | RPA 固定界面与固定脚本；智能体理解语义并动态选择工具             |
| 单智能体 vs 多智能体      | 任务是否需要专长分工与权限隔离，多体带来成本与误差放大              |
| 微服务 vs 智能体        | 微服务无状态、可编排、被调用；智能体有状态、会推理、主动决策           |
| 数字孪生 vs 智能体       | 数字孪生是物理实体在数字空间的映射与同步；智能体是数字空间的推理与执行主体    |
| RAG vs 微调         | RAG 外部知识可溯源可更新，微调改权重成本高且难溯源              |

### 12. 案例与论文的答题落点

- **案例三类题型**：架构选型对比题（智能体平台后端架构）、链路还原题（LLM 端到端交互流程、推理流程填空）、列举题（中间件类别与典型产品）。答题一律“痛点对应方案、落到具体组件名”。
- **选做与必做策略**：案例 5 题选 3 题且第 1 题必答；AI 智能体题通常作为选做出现，若 UML 与软件工程建模是强项，应优先保证必答题与建模题，AI 题作为拉分项准备。
- **论文框架**：背景与智能体能力短板 → 智能体体系架构（运行主轴、记忆、工具、编排、RAG）→ 工程化护栏与评测 → 实施过程与效果数据 → 不足与改进方向。仓库已有《论文范文二：大模型智能体》可直接套用改写。

## 三、备考建议

- **上午选择题**：重点记四组对比，工作流与智能体、提示工程与 RAG 与微调、消息队列与缓存、单智能体与多智能体；再记 RAG 七步流程、上下文窗口、KV 缓存、Softmax 归一化等大模型基础机制，这批考点常以“属于/不属于”形式出现。
- **案例分析**：按三条主线复习，架构选型（微服务与一体化在并发、调度、安全、扩展四维上的强弱）→ 推理链路（接入、网关、RAG、推理、后处理审核、流式返回）→ 护栏与评测（输入脱敏、输出审核、权限最小化、人工复核、回归评测）。每条主线都要能落到具体组件名。
- **论文写作**：2026 年上半年论文已考 LLM 辅助测试，下半年应重点准备大模型智能体方向的选题，套用“体系架构 + 工程化要点 + 实施效果 + 不足改进”四段式，注意每段控制在八行以内并给出前后对照数据。
- **答题规范**：条数约等于分值，超出字数限制要扣分，术语要具体，避免“提升了效率”这类空话，改为“自动解决率从 0 提升到 82%”这类带数据的表述。
- **风险提示**：AI 案例与论文题属于新技术方向，命题形式不稳定，应以“教材可迁移知识”为主干（架构、网关、缓存、消息、治理、UML），把 AI 术语作为外壳套在主干上。
