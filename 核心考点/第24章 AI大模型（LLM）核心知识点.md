# 第24章 AI大模型（LLM）核心知识点

## 一、真题考情概览

- **2024年至2025年（铺垫期）**：AI 相关内容主要出现在综合知识的选择题中，考查机器学习分类、神经网络基本结构、训练与过拟合等基础概念；案例分析与论文尚未以大模型为独立主题，但智能客服、智能运维、测试用例生成等场景已作为业务背景频繁出现。
- **2025年下半年**：案例分析必答题为需求工程，选答题覆盖结构化分析与设计、缓存数据库、嵌入式、Web 系统设计；论文四题为软件测试、设计模式应用、系统成本效益分析、云计算运维。大模型仍未单独命题，属于背景词。
- **2026年上半年（关键转折）**：论文第一题考“LLM 大模型语言辅助测试”，要求说明 LLM 生成测试用例的具体实现、使用 LLM 的优势与问题及应对措施、其局限性与解决办法；案例分析第五题考“Web 应用与 AI 智能体融合平台”，涉及后端架构选型、负载均衡与中间件。综合知识仍以传统考点为主，AI 占比有限但已稳定出现。
- **命题走向**：从“什么是大模型”转向“大模型怎么落进系统”，题型以概念辨析、链路还原、方案与选型对比为主。LLM 与智能体的分工要分清：LLM 是推理内核，智能体是带规划、工具、记忆的工程外壳（详见第23章）。以下真题均为回忆版，个别表述与官方版本可能有出入。

## 二、核心知识点总结

### 1. Transformer 与自注意力（概念题高频）

- 结构：编码器与解码器均由多层堆叠，每层为“多头自注意力 + 前馈网络”，配残差连接与层归一化。
- 自注意力：输入分别映射为 Q、K、V 三组向量，用 Q 与 K 的点积算相关性权重，再对 V 加权求和；点积除以维度的平方根，防止数值过大导致 Softmax 饱和、梯度消失。
- 多头：多组独立参数并行计算后拼接，从不同子空间捕捉语法、指代、语义等关系。
- 位置编码：自注意力本身没有顺序感，必须注入绝对位置（正弦编码）或相对位置（RoPE、ALiBi），否则语序信息丢失，这是“为什么需要位置编码”的标准答法。
- 三种主流结构：纯编码器（BERT，掩码语言模型，擅长理解与分类）、纯解码器（GPT，自回归预测下一 token，擅长生成）、编码解码（T5，适合翻译与摘要）。
- 复杂度：标准注意力时间与显存随序列长度平方增长，这是长上下文成本高的根源，也是 FlashAttention、稀疏注意力、线性注意力的动因。

### 2. 分词、Token 与上下文窗口

- 分词：把文本切成 token，主流为 BPE、WordPiece 子词切分，兼顾词表规模与未登录词；中文一个汉字通常不足一个 token，英文长词常被切成多个子词。
- token 直接决定计费、上下文长度与生成成本，估算容量时按 token 而非字数。
- 上下文窗口：模型单次可见的 token 上限，输入与输出共享额度，输出另有最大生成长度限制；超限要截断、摘要或分块续写。
- 长上下文三策略：检索式（RAG 按需召回）、压缩式（摘要与信息抽取）、缓存式（KV 缓存复用前缀）。代价一是注意力平方复杂度，二是“中间遗忘”，即长文本中段信息利用率明显下降。

### 3. 训练三阶段（SFT 与对齐必考辨析）

- 预训练：海量无标注语料做下一 token 预测，得到基座模型，掌握语言规律与世界知识，但不会听指令。
- 指令微调（SFT）：用“指令-回答”配对数据做监督训练，让模型学会按意图与格式作答。
- 对齐：RLHF 先训练奖励模型再用强化学习优化；DPO 直接用偏好对优化，省去奖励模型与强化学习，工程更简单，是当前主流替代方案。
- 三者关系：预训练决定“知道什么”，SFT 决定“会不会按要求答”，对齐决定“答得合不合人类偏好与安全规范”。
- 数据质量比数量更重要，去重、清洗、配比直接影响效果；持续训练要警惕灾难性遗忘，即学新任务时旧能力退化。

### 4. 参数高效微调（案例选型常考）

- 全量微调：更新全部参数，效果上限最高，但显存与算力开销大，每个任务要存一份权重。
- LoRA：冻结基座，旁路注入低秩矩阵（ΔW = BA），只训练两个小矩阵，显存低、可插拔、多任务切换只需换适配器。
- QLoRA：基座先做 4bit 量化再挂 LoRA，进一步压低显存门槛，适合单卡与私有化场景。
- 适配器与提示学习（Prompt/Prefix Tuning）：前者插入小模块，后者只调连续提示向量，同属参数高效路线。
- 选型判据：数据量小、任务多、算力紧优先 LoRA；需要深度改变领域表达且数据充足，才考虑全量微调。

### 5. 推理过程与解码策略

- 自回归生成：每步输出一个 token 并回填上下文，逐 token 串行，因此时延天然高于传统接口调用。
- 两阶段：预填充（prefill，一次性算完输入，决定首 token 时延 TTFT）与解码（decode，逐 token 生成，决定每 token 时延 TPOT）。二者瓶颈不同、优化手段不同，是性能分析题的落点。
- 解码策略：贪心（确定性强、易重复）、束搜索（质量好但开销成倍）、温度采样（温度低更确定、高更发散）、top-k 与 top-p 核采样（截断长尾、降低胡言）、重复惩罚。
- 结构化输出：约束解码或函数调用 schema，保证返回可被程序稳定解析。
- 关键指标：TTFT、TPOT、吞吐（tokens/s）、并发数、单位任务成本，五者互相牵制，扩容不能只加副本。

### 6. 推理加速与部署优化

- KV 缓存：缓存历史 token 的 Key/Value，避免每步重算；显存占用随上下文线性增长，是并发能力的主要瓶颈。
- PagedAttention 与连续批处理：把 KV 缓存分页管理、动态拼批，显著提升显存利用率与吞吐，这是 vLLM 一类推理框架的核心机制。
- 量化：权重 INT8/INT4（W8A16、W4A16），以少量精度换显存与速度；KV 缓存量化可进一步降显存。
- 蒸馏与剪枝：小模型学习大模型的输出分布，或去掉冗余结构，用于端侧与低成本场景。
- MoE 混合专家：稀疏激活，总参数大而单次计算只走部分专家，兼顾能力与成本。
- 并行策略：张量并行（层内切分）、流水并行（层间切分）、数据并行（多副本），大模型推理常组合使用。

### 7. 向量化与语义检索（RAG 的地基）

- 嵌入：把文本映射为稠密向量，语义相近则向量距离近；相似度常用余弦相似度或内积。
- 与传统检索的分工：BM25 与倒排索引擅长关键词精确匹配，向量检索擅长同义改写与语义泛化，双路召回再加融合的混合检索最稳。
- 近似最近邻索引：HNSW 为图索引，召回高但内存占用大；IVF 为聚类倒排，速度快但需调探测数；PQ 做乘积量化，压缩向量但损失精度。
- 向量数据库选型指标：维度与数据规模、召回率与 QPS、元数据过滤能力、是否支持混合检索、水平扩展与运维成本。代表产品有 Milvus、Qdrant、Chroma、PGVector、Elasticsearch。
- 分块策略：按语义边界切分、保留重叠窗口防语义被切断、采用父子块（小块检索、大块喂给模型）。

### 8. RAG 流程与效果评估（与第23章互补）

- 七步主线：加载 → 分块 → 向量化 → 入库 → 召回 → 重排 → 组装提示并生成、附引用出处。
- 两段检索：粗召回保证覆盖率，重排（交叉编码器）保证精度，二者分工是准确率关键。
- 生成约束：要求只依据召回内容作答、标注来源、无依据时明确拒答。
- 评估指标：召回率与命中率衡量检索环节，忠实度衡量是否忠于材料，答案相关性衡量是否答到点上；离线跑评测集，线上看人工反馈与差评归因。
- 常见失效：知识未入库、分块切碎语义、召回不足、缺少重排、提示过长挤掉关键信息。

### 9. 提示工程与提示注入

- 基本范式：零样本、少样本（给示例定格式）、思维链（要求分步推理）、角色与约束设定。
- 结构化提示：按“输入、任务、约束、输出格式”四段组织，比长篇自然语言更稳定。
- 提示注入：用户输入夹带“忽略以上指令”一类内容劫持模型行为，属输入侧安全风险；防护靠指令与数据分隔、输入过滤、权限最小化、工具调用白名单。
- 越狱：诱导模型绕过安全策略；防护靠系统提示加固、输出审核、红队测试。
- 边界：提示工程解决“怎么问”，不能替代知识更新（RAG）与能力改变（微调）。

### 10. 幻觉、评测与模型选型

- 幻觉两类：事实性幻觉（与客观事实不符）、忠实性幻觉（与给定材料矛盾）。
- 成因：模型按概率续写而非查证、训练数据噪声、长上下文中间信息丢失、提示缺乏约束。
- 抑制：RAG 加引用溯源、降低温度、明确要求“不知道就说不知道”、关键结论人工复核、输出结构化校验。
- 评测方法：构建业务评测集做回归测试；客观题看准确率，生成题看忠实度与人工评分；LLM-as-judge 可规模化但有偏差，需抽样人工校准。
- 选型维度：能力（推理、代码、多模态）、上下文长度、时延与吞吐、单价与私有化可行性、微调与工具调用支持、数据合规。闭源 API 上线快、能力强但数据出域；开源私有化数据可控、可微调，但需自建算力与运维。

### 11. LLM 与传统技术结合（案例落点）

- LLM 与数据库：Text2SQL 把自然语言转成 SQL，难点在库表 Schema 链接、歧义消解与结果校验；工程上用 Schema 裁剪、少样本示例、执行报错自纠正、只读账号与行级权限兜底。
- LLM 与检索：RAG 是最常见的落地形态，见本节第8条。
- LLM 与规则、工作流：确定性环节仍用规则与状态机，LLM 只承担语义理解与生成，避免全链路不可控。
- LLM 与智能体：LLM 提供推理，智能体提供规划、工具与记忆，完整架构见第23章。
- 与传统机器学习的分工：分类、回归、推荐等判别式任务，小模型成本低、可解释、输出稳定；LLM 适合非结构化理解、生成与跨任务泛化，不能用它一刀切替代。

### 12. 易混概念辨析（选择题高频）

| 概念对 | 判据（一句话区分） |
| --- | --- |
| 预训练 vs 微调 | 学语言与世界知识 vs 学任务与输出格式 |
| SFT vs RLHF/DPO | 监督学“怎么答” vs 用偏好学“哪种答更好” |
| LoRA vs 全量微调 | 只训低秩旁路、可插拔 vs 更新全部参数、成本高 |
| RAG vs 微调 | 外挂知识、可溯源可更新 vs 改权重、成本高且难溯源 |
| 提示工程 vs RAG | 怎么问 vs 喂什么 |
| 向量检索 vs 关键词检索 | 语义泛化 vs 精确匹配，混合检索最优 |
| 温度 vs top-p | 调概率分布平滑度 vs 截断候选集范围 |
| KV 缓存 vs 缓存中间件 | 推理内部张量复用 vs 业务数据缓存 |
| LLM vs 智能体 | 推理内核 vs 含规划、工具、记忆的工程系统 |

### 13. 安全与合规底线

- 数据：训练与推理数据不出域、脱敏、租户隔离，敏感行业优先私有化部署或专有实例。
- 内容：生成内容审核与标识，敏感话题配置拒答策略。
- 权限：模型不直接持有数据库凭证，统一经工具网关以最小权限访问，调用日志留痕可审计。
- 供应链：核查模型来源与许可证、依赖组件漏洞，密钥集中管理。

## 三、备考建议

综合知识以概念辨析为主，优先掌握四组对比（预训练与微调、SFT 与对齐、RAG 与微调、向量检索与关键词检索），再记 Transformer 自注意力与位置编码、上下文窗口、KV 缓存、两级时延指标这几个可出计算题或“属于/不属于”判断题的点。

案例分析按三条线准备：性能线（TTFT、TPOT、吞吐与并发，对应 KV 缓存、PagedAttention、量化与并行）、知识线（分块、召回、重排、引用溯源与幻觉抑制）、成本线（token 计费、缓存命中、模型分级路由）。答题要落到具体机制名，避免只写“优化性能”。

论文方面，2026 年上半年已考 LLM 辅助测试，后续大概率继续围绕大模型在需求、设计、测试、运维中的落地命题，建议按“业务痛点、技术方案、实施过程、效果数据、不足改进”五段准备，并与第23章智能体素材共用案例背景。复习时抓机制与选型判据即可，不必记参数规模与榜单排名。
