# TCP/IP 协议体系：分层模型、TCP 连接管理与 UDP

> 说明：本文按 ASD-STE100 简明技术英文写作规范的中文表达写成，句子简短、每句一个主题、动词用主动语态，便于快速通读记忆。

## 一、TCP/IP 四层模型

TCP/IP 协议是互联网通信的规则集。它把通信过程分成四个层次。每一层只做一类工作，并为上一层提供服务。

网络接口层负责在物理网络上传输数据。它把数据转换成电信号或光信号，并处理硬件地址。以太网协议和 Wi-Fi 协议都属于这一层。这一层不保证数据一定到达。

网际层负责把数据从源主机送到目标主机。它使用 IP 地址来确定数据的去向。IP 协议是这一层的核心协议，它为数据包选择转发路径。网际控制报文协议 ICMP 报告传输中的错误。地址解析协议 ARP 把 IP 地址解析成硬件地址。

传输层负责建立端到端的数据传输。它把数据交给正确的应用程序。端口号用来区分不同的应用程序。传输层有两个协议：TCP 和 UDP。

应用层负责为用户提供具体的网络服务。它把数据组织成应用程序能理解的格式。超文本传输协议 HTTP 用于网页传输。域名系统协议 DNS 把域名解析成 IP 地址。简单邮件传输协议 SMTP 用于发送电子邮件，文件传输协议 FTP 用于传送文件。

数据在发送时从上层向下层传递，每一层都加上本层的头部信息。接收时数据从下层向上层传递，每一层再取出自己的头部信息。这样每一层只需与相邻层配合，就可以完成通信。

## 二、TCP 三次握手

TCP 提供可靠传输。它先建立连接，再传送数据，最后关闭连接。建立连接的过程需要三次报文交换，通常称为三次握手。

第一次握手时，客户端向服务器发送一个同步报文。报文里含有客户端的初始序列号。发送后客户端进入同步已发送状态，并等待服务器的回答。

第二次握手时，服务器收到同步报文。服务器把自己的同步报文和确认报文一起发给客户端。确认号等于客户端初始序列号加一。发送后服务器进入同步已接收状态。

第三次握手时，客户端收到服务器的同步报文。客户端再向服务器发送一个确认报文，确认号等于服务器初始序列号加一。发送后连接建立，双方进入连接已建立状态。

三次报文交换可以同时确认双方的发送能力和接收能力。

## 三、TCP 四次挥手

数据传输结束后，TCP 需要断开连接。断开过程需要四次报文交换，通常称为四次挥手。

第一次挥手时，主动关闭方发送一个结束报文。报文里含有当前序列号。发送后主动关闭方进入结束等待一状态。

第二次挥手时，被动关闭方收到结束报文。被动关闭方立即发送一个确认报文，确认号等于结束报文序列号加一。此时被动关闭方进入关闭等待状态，主动关闭方进入结束等待二状态。被动关闭方可能还有未发送完的数据，因此暂时不发送结束报文。

第三次挥手时，被动关闭方把剩余数据全部发送完毕。然后被动关闭方向主动关闭方发送自己的结束报文。发送后被动关闭方进入最后确认状态。

第四次挥手时，主动关闭方收到结束报文。主动关闭方发送最后一个确认报文，确认号等于结束报文序列号加一。发送后主动关闭方进入时间等待状态，并等待两倍的最长报文生存时间。等待结束后主动关闭方才真正关闭连接。被动关闭方收到确认报文后立即关闭连接。

挥手需要四次报文，是因为确认报文和结束报文通常分开发送。握手时这两个报文可以合并发送，因此握手只需要三次。

## 四、UDP 协议

UDP 是传输层的另一个协议。它在 IP 协议之上提供最简单的端到端传输服务。UDP 不建立连接，发送方可以直接发出数据。

UDP 报文的头部只有八个字节。头部包含源端口、目标端口、报文长度和校验和。校验和用来检测传输中产生的错误。

UDP 不保证数据一定到达。数据丢失后 UDP 不会重传，数据乱序后 UDP 也不会重新排序。UDP 没有流量控制，也没有拥塞控制。接收方处理不过来时，数据就被丢弃。因此 UDP 提供的是尽力而为的传输服务。

UDP 的开销很小。它不需要维护连接状态，也不需要交换控制报文。报文头部比 TCP 短得多，发送前也没有等待时间。所以 UDP 的传输延迟低，适合对时间敏感的应用。

域名系统 DNS 使用 UDP 来查询域名。网络语音和视频会议使用 UDP 传送实时媒体。在线游戏使用 UDP 同步玩家状态。动态主机配置协议 DHCP 也使用 UDP 分配网络地址。这些应用更重视速度，可以容忍少量数据丢失。

## 五、TCP 与 UDP 的选择

TCP 和 UDP 解决不同的问题。TCP 保证可靠和有序，但开销大、延迟高。UDP 不保证可靠，但简单快速。应用程序根据自己的需要选择其中一个协议。
