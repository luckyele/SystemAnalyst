## P0-1 软件架构与集成

> 对应错题：59、60、74、75、79、80、82、83、84、94　｜　权重：案例第 1 题（必选）+ 论文

### 1.1 架构风格五大类（必背）

| 类别 | 代表风格 |
|---|---|
| 数据流 | 批处理、管道-过滤器 |
| 调用返回 | 主程序-子程序、面向对象、分层 |
| 独立构件 | 进程通信、事件驱动（隐式调用） |
| 虚拟机 | 解释器、规则系统 |
| 仓库 | 数据库系统、超文本系统、黑板系统 |

**黑板风格 vs 管道-过滤器（59）**
- 黑板：**无确定解题顺序**、由数据（状态）驱动、中央共享数据结构，适合复杂问题求解（信号处理、语音识别、图像识别）。
- 管道-过滤器：**顺序单向**数据流、过滤器间无交互、适合批处理与流式处理。
- 判据：**要不要"中心共享数据 + 驱动式求解"** —— 要则黑板。

**五大类变式命题（60）**：命题常按"拓扑结构 / 控制方式 / 数据传递"重新组合设问，需回到"数据怎么流、控制谁主导"判断，而非背名字。

### 1.2 SOA 与 Web 服务

**服务建模三阶段（74）**：**发现（找）→ 规约（定）→ 实现（做）**
- 发现：自上而下 / 自下而上 / 中间对齐 → 得到候选服务
- 规约：服务分类、是否暴露、服务编排 / 服务库 / 接口模式
- 实现：划分到服务构件、三种实现方式 + 技术可行性分析

**异构系统集成选总线（75）**
- 触发条件：**传输协议不同 + 数据格式不同 + 要求松耦合** → 选总线（ESB）
- 总线集中完成：协议转换、格式转换、消息路由
- 反例排除：共享数据库（紧耦合，且"数据集成 ≠ 系统集成"）、RPC（同步紧耦合，两两适配数 n(n-1)/2）
- 口诀：**"异构集成找总线，协议格式它来变"**

**ESB 三层（80）**

| 层 | 职责 |
|---|---|
| 接入层 | 多协议接入与适配（管"进"） |
| 核心层 | 分发/订阅、智能路由、转换仲裁、QoS（管"跑"） |
| 业务流程层 | BPEL 业务流程编排（管"编排"） |

**REST（82）**
- 本质：**混合架构风格** = 客户/服务器 + 无状态 + 缓存 + 统一接口 + 分层系统
- 五优点：标准成熟、URI 直达资源、缓存+无状态伸缩强、轻量低成本、浏览器可测
- 陷阱：**"服务代理 / UDDI / 注册中心"出现在 REST 语境即判错**（那是传统 Web 服务的方式）

**WSDL / SOAP / REST 关系（84）**
- 传统三件套：**SOAP（XML 消息协议）+ WSDL（接口描述）+ UDDI（注册发现）**，三者独立标准、按需组合。
- REST：URI + HTTP 动词暴露服务，通常**不依赖 WSDL**（用 WADL / OpenAPI）。
- 口诀：**XML 系 = SOAP/WSDL/UDDI；JSON 轻量 = REST；出现"强制"表述即错**

### 1.3 视图、方法与质量属性

**4+1 视图（79）**

| 视图 | 关注点 | 面向角色 | 对应 UML |
|---|---|---|---|
| 逻辑 | 功能需求 | 用户 / 分析员 | 类图、包图 |
| 开发 | 代码组织 | 程序员 | 组件图 |
| 进程 | 并发与性能 | 系统集成人员 | 顺序/活动/状态图 |
| 物理 | 软硬件部署 | 系统工程师 | 部署图 |
| 场景（+1） | 需求驱动与验证 | 全体 | 用例图 |

- 口诀：**"功能逻辑、代码开发、跑起来进程、放上去物理、用例串全场"**

**ABSDM 六子过程（83）**：**需求 → 设计 → 文档化 → 复审 → 实现 → 演化**
- 口诀：**"需设文复实演"**
- 排除项："体系结构分析"不在其中；架构评估方法（SAAM / ATAM / CBAM）不是子过程

**质量属性辨析（69）**
- **可用性**：故障检测、恢复与修复（MTTR、MTBF）→ **"恢复慢 = 可用性"**
- **可修改性**：变更、扩展、二次开发的代价 → **"改造耗时长 = 可修改性"**
- **性能**：只看响应时间 / 吞吐量 / 资源利用率

**架构案例五大类考点（94）**
1. 软件架构设计（每年 1–2 题，第 1 题必选：质量属性 / 架构风格 / 评估 / MVC / SOA / ESB / J2EE）
2. 系统开发基础（几乎年年考：UML 图关系、设计模式识别、DFD/E-R、信息安全、进度与关键路径）
3. 数据库系统（偶尔：新技术对比 / 反规范化 / 主从复制 / 负载均衡）
4. 嵌入式系统（几乎每年，选做：实时性 / 可靠性 / 容错）
5. Web 应用开发（常结合架构）
- 应试：**先做第 1 题；选做题先扫再选；按考频分配时间**

## P0-2 设计模式

> 对应错题：72、73、77、95、96

### 2.1 三分类 5/7/11（72 / 95）

| 分类 | 数量 | 模式清单 |
|---|---|---|
| 创建型 | 5 | 工厂方法、抽象工厂、单例、建造者、原型 |
| 结构型 | 7 | 适配器、装饰器、代理、外观、桥接、组合、享元 |
| 行为型 | 11 | 策略、模板方法、观察者、迭代子、责任链、命令、备忘录、状态、访问者、中介者、解释器 |

- 口诀：**"创建管造、结构管拼、行为管交互"**；**"创建五、结构七、行为十一"**
- 解题铁律：**每个选项里的两个模式都要查** —— 错误项惯用"一个对一个错"混搭
- 高频误判：模板方法（行为型，非创建型）、桥接（结构型，非行为型）、外观（结构型）、中介者（行为型）

### 2.2 类行为 vs 对象行为（73）
- **类行为只有 2 种**：解释器、模板方法；其余 9 种均为对象行为。
- 口诀：**"类行为只有解释模板，类结构只有适配器"**

### 2.3 场景识别（77 / 96）

**组合模式（77）**：Component + Leaf/Composite **并列继承** + Composite **聚合 Component 自身**（递归树形）→ 结构型
- 与装饰器区分：装饰器是"层层包裹"，组合是"叶子/容器并列递归"

**访问者模式（96）**：**对象结构稳定 + 操作频繁新增 + 双重分派（Accept / Visit）**→ 行为型
- 适用场合标准表述：**"对象结构的类很少改变，但经常需要在此结构上定义新的操作"**
- 干扰项对应：A=状态、C=策略、D=观察者
- 关键指纹：必须同时出现 `Accept()` 与 `Visit()` 回调

## P0-3 需求工程与开发过程

> 对应错题：85、88、89、90、91、92、93、109、111、112、116

### 3.1 需求分析方法与产物

**方法三大类（88）**：结构化分析（SA）、面向对象分析（OOA）、面向问题域分析（PDOA）
- **"面向过程"不属于需求分析方法**（它是编程范式/设计方法）
- 审题注意"不包括 / 不属于"

**输入与输出（109）**
- 输入：系统规约、软件项目计划
- 输出：**软件需求规格说明（SRS）** + 数据/功能/行为模型
- 阶段定位：**"做什么"，不定"怎么做"**
- 判据：需求分析**不产出系统规约**（系统规约是系统级输入，上一层级）

**需求三层次（111）**

| 层次 | 回答什么 | 关键词 |
|---|---|---|
| 业务需求 | 为什么做 | 目标、范围 |
| 用户需求 | 用户要做什么 | 任务、场景 |
| 系统需求 | 系统做成什么样 | 功能 + 非功能 + 设计约束 |

- 陷阱："数据需求"**不是**需求层次

### 3.2 开发过程模型

**RUP 四阶段（112）**：**初始 → 细化 → 构建 → 移交**
- 初始：定边界与风险；细化：**定架构**（架构决策在此，不在初始）；构建：造产品（并行制造）；移交：交付用户
- 三大特点：用例驱动、架构为中心、迭代增量
- 口诀：**"初始定边界与风险 → 细化定架构 → 构建造产品 → 移交交用户"**

**RAD vs SDLC（116）**
- SDLC（瀑布式）：前提是**需求明确且稳定**
- RAD 触发信号：**需求不明确 + 工期短 + 多系统复杂交互**
- RAD 基本思想：用户参与 + 快速原型迭代 + 并行开发 + 构件复用 + 工具支撑（CASE / 4GL / 代码生成器）
- 口诀：**"需求稳用 SDLC，需求变、工期紧用 RAD"**

**敏捷开发（93）**
- 4 条价值观：个体与互动、可工作软件、客户合作、响应变化
- 12 条原则（"基本原则"两层都要答，勿只写 4 条价值观）
- 结对编程：**两人一机 + 两种角色（驾驶员/领航员）+ 角色互换 + 价值（评审/共享）**
- 注意："高于"≠"否定"（不是不要文档/计划）

**开发模型选型（90，论文）**：瀑布线性、原型试错、增量累加、螺旋防险、喷泉回溯、变换证明、V 型配对、RUP 迭代、敏捷应变
- **高风险项目必选螺旋模型**；模型无最优、只有最合适

### 3.3 项目管理

**项目风险管理（91，论文）**：规划 → 识别 → 估计 → 评价 → 应对规划 → 监控
- 四应对策略：规避（消除来源）/ 转移 / 减轻（降概率或影响）/ 接受
- 区分：风险估计（单个风险的概率与影响）vs 风险评价（全部风险排序分级）
- 风险 = **未发生**的潜在事件（写成已发生的问题即跑题）

## P0-4 软件测试与质量

> 对应错题：64、65、66、67、68、69、70、71

**测试过程六阶段（71）**：**项目需求分析 → 制订测试计划 → 设计测试文档 → 搭建测试环境 → 执行测试 → 缺陷管理**
- 最大陷阱：**漏掉"项目需求分析阶段"**（体现测试左移）
- 三组维度不可混：**测试过程**（怎么走）/ **测试阶段级**（测谁）/ **测试类型方法**（用什么手段）

**黑盒测试九法（66）**：功能分解、等价类划分、边界值分析、判定表、因果图、状态图、随机测试、错误推测、正交试验法
- 因果图 → 转换为判定表；判定表列数 = 2ⁿ
- 口诀：**"黑盒看'做什么'，白盒看'怎么做'"**
- 分组速记：输入域（等价类/边界值）→ 逻辑组合（判定表/因果图/正交）→ 功能行为（功能分解/状态图）→ 经验随机（错误推测/随机）

**MC/DC 覆盖准则（68）**
- C/DC = 判定覆盖 + 条件覆盖（各真假至少出现一次）
- MC/DC = C/DC + **每个条件能独立影响判定**
- **MC/DC 用例数下界 = n + 1**（n 为无耦合条件数）；`A OR B` 需 **3 例**
- 提醒：覆盖率达标 ≠ 质量合格

**Web 测试类型辨析（70）**
- **性能测试是上位统称**（含负载、压力、并发、吞吐、稳定性等子类）
- 负载测试 = 压到**预期值**看表现；压力测试 = 超出**极限**找崩溃点
- 兼容性测试 = 不同浏览器 / OS / 分辨率下能否正常工作

**容错冗余四类（64）**：结构冗余、信息冗余、时间冗余、冗余附加技术
- 只有**结构冗余**再分：静态（TMR，同时在线+表决器+不切换）、动态（热备/冷备，故障才切换）、混合
- 口诀：**"热备冷备 = 结构冗余-动态；校验码 = 信息冗余；重做 = 时间冗余；表决器 = 附加技术"**
- 判据：**静态 vs 动态，看是否切换**

**负载均衡（65）**
- 垂直扩展 Scale-up vs 水平扩展 Scale-out
- 分层判据：**看 IP/端口 = 传输层（四层）；看 HTTP 内容/URL = 应用层（七层）**
- 会话保持（`sh`/Cookie 粘同一机）**≠** 会话共享（Redis 集中存储）
- 案例分析答题：先答"问题"再答"改进"，多角度归因

**系统测试与性能测试（67，论文）**
- 系统测试对象 = 完整集成后的系统、真实环境、验证配置项与合同要求
- 系统测试管理七活动：计划 → 设计 → 环境/配置 → 执行监控 → 缺陷管理 → 评审报告 → 收尾
- 性能测试类型：负载、压力、并发、稳定性（疲劳）、容量、基准、峰值

## P1-5 信息化战略与集成

> 对应错题：97、100、103、104、105、113

**BITA vs EITA（100 / 104）**
- **BITA**：以**业务为导向**的、全面的 IT 管理咨询实施方法论 → **"业务不满足 → BITA"**
- **EITA**：分析企业战略、帮助**制订 IT 战略**、指导**投资决策** → **"IT 架构乱 → EITA"**
- 陷阱：**CITA / DITA 是杜撰干扰项**，教材只有 BITA 与 EITA
- 层级归位：战略集成方法层 = BITA/EITA；变革手段层 = BPR/BPM；系统产品层 = ERP/CRM/SCM

**ISSP 四大规划方法（103）**

| 方法 | 提出者 | 特征 |
|---|---|---|
| 战略集合转化法 | King（SST） | 战略集 → 系统战略集 |
| 战略栅格法 | McFarlan | 两维度 → 四象限（战略型/工厂型/支持型/转向型） |
| 价值链分析法 | Porter | 基本活动 + 支持活动，**以集成为核心** |
| 信息工程法 | James Martin | **以数据为中心** |

- 口诀：**"转化看 SST，象限看栅格，内外集成看价值链，数据中心看信息工程"**

**EAI 五个集成层面（105）**：界面集成（表示集成）→ 平台集成 → 数据集成 → 应用集成（控制集成）→ 过程集成（业务流程集成）
- 口诀：**"界面最浅最常用，平台治底，数据打底，应用近实时，过程最高管流程"**
- 注意：应用集成 = 控制集成（**同一层两个名字，勿数成六层**）

**DSS 基本组成（97）**：数据部分 + 模型部分 + **推理部分**（知识库 + 知识库管理系统 + 推理机）+ 人机交互部分
- 口径区分：问"**两库结构**"只答数据库 + 模型库；问"**基本组成部分**"须数齐四部分
- 陷阱："决策算法子系统"是杜撰名词，决策算法属模型库

**数据字典六类条目（113）**：数据元素、数据结构、数据流、数据存储、加工逻辑、外部实体
- 数据流（**流动**：来源→去处）vs 数据存储（**静止**存放结构）
- 加工逻辑须含输入/输出数据流，靠**判定树 / 判定表 / 结构化语言**描述
- 口诀：**"元素最小、结构组合、数据流流动、数据存储落盘、加工逻辑变换、外部实体出边界"**

## P1-6 数据持久化与交互辨析

> 对应错题：106、107、108、114、115

**ORM 自动化程度（106 / 107）**
- 抽象层次排序：**JDBC < iBatis/MyBatis < Hibernate**
- 身份定性：JDBC 是最底层 API；JDO / JPA 是**规范**；iBatis/Hibernate/MyBatis 是**框架**
- 口诀：**"小巧快用 iBatis，强大全自动 Hibernate，底层手动 JDBC，规范标准是 JPA"**
- 206/107 互为正反面：题干出现"小巧/半自动"→ MyBatis；出现"全自动"→ Hibernate

**数据库交互四种方式（108）**

| 方式 | 判据 |
|---|---|
| 嵌入式 SQL | SQL **直接写入**宿主语言（预编译、主变量 EXEC SQL） |
| 库函数（API） | SQL 当作**函数字符串参数** |
| ODBC / JDBC | **统一接口**屏蔽数据库差异 |
| ORM | **不写 SQL**，只管对象 |

- 演进：嵌入式 SQL → 库函数 → ODBC/JDBC → ORM（抽象升、效率升、SQL 可控性降）

**分布式数据库（114）**
- 三要素：**数据分布 + 场地自治 + 全局应用**
- 三大性能技术：数据分片、数据复制、分布式查询优化
- 判据：**读多写少 → 数据复制**（副本/读写分离）；写多或量大 → 数据分片；混合 → 分片 + 复制
- 组件归类：HAProxy/LVS = 负载均衡；Squid/Memcached = 缓存；FastDFS/HDFS/MooseFS = 分布式文件系统；JBoss/Tomcat/Jetty = Web 应用服务器；MongoDB/MySQL = 数据库

**微服务组件（115）**
- API 网关：**"入口 + 鉴权 + 限流"**三件套（+路由、协议转换/聚合、监控日志、灰度发布、缓存）
- 服务注册发现：**"注册 + 发现 + 健康检查"**三件套（+变更通知/本地缓存更新）
- 关键区分：**注册中心（服务地址/状态）≠ 配置中心（配置参数）**；健康检查是注册中心区别于 DNS 的关键
- 注册中心 CAP 选型：Eureka（AP）、Consul/Zookeeper（CP）、Nacos（AP/CP 可切）

## P1-7 UML 元知识

> 对应错题：98、99、101、102、110

**UML 三层结构（102）**：**构造块 + 规则 + 公共机制**
- 基本构造块 3 类：**事物、关系、图**
- 规则 5 条：命名、范围、可见性、完整性、执行
- 公共机制 4 类：规格说明、修饰、公共分类、扩展机制
- 口诀：**"块—则—制"**；**"事、关、图"**；**"名范可完执"**；**"规修分扩"**
- 措辞对应：多个关联事物的集合 = 图；把事物连起来 = 关系；基本成分 = 事物；语义细节描述 = 规格说明

**UML 四类关系与线型（98）**

| 关系 | 线型 |
|---|---|
| 依赖 | 虚线 + 开口箭头 |
| 关联 | 实线（聚合加空心菱形、组合加实心菱形） |
| 泛化 | 实线 + 空心三角 |
| 实现 | 虚线 + 空心三角 |

- **包含 «include» 与扩展 «extend» 本质都是依赖**；泛化无论出现在哪种图里都是泛化
- 口诀：**"含扩本为依赖，泛化仍是泛化"**

**扩展机制三件套（99）**：**约束 `{}`、构造型 `«»`、标记值 `{tag=value}`**
- 易混："修饰"指可见性 `+ - #`、多重性 `1..*`、抽象斜体
- 层级：构造型 ⊂ 扩展机制 ⊂ 公共机制

**活动图标注（101）**
- 控制流可加三类：流名称（无方括号）、**监护表达式 `[condition]`**（方括号布尔条件）、动作名（写在节点内部）
- 口诀：**"带方括号 → 监护表达式；不带方括号的文字 → 流名称；写在节点内 → 动作名"**

**Petri 网与工作流（110）**
- Petri 网：**库所 places（圆圈）、变迁 transitions（矩形）**，用有向弧连接
- 工作流参考模型核心模块 = **工作流执行服务**（非引擎）
- 口诀：**"执行服务是枢纽，引擎跑流程，定义工具画流程"**

## P1-8 项目管理计算

> 对应错题：89、92

**资源约束工期计算（89）**
- 步骤：先算关键路径得**下界** → 列**冲突作业对**（人数之和 > 上限者不能并行）→ 冲突作业串行、小作业填缝
- 陷阱：忽略无紧前也无紧后的作业；把"必须连续进行"当摆设（禁止拆分作业）
- 结论：资源受限后真实工期 **≥ 关键路径下界**

**NPV 投资决策（92）**
- NPV = Σ(净现金流量 × 折现系数) = 收益现值 − 投资现值；**NPV ≥ 0 可行，越大越优**
- 投资额相同比 NPV；投资额不同比 **NPVI（现值指数）**
- 陷阱：**建设期"年初投资"与运营期"年末净现金流"折现年份错位**
- 可行性四维度：经济、技术、法律、用户使用（法律侵权是采分点）

## P2-9 零散补漏

**人机界面黄金三原则（81）**：置用户于控制之下、减少记忆负担、保持界面一致性
- 判据：涉及**用户主动权 → 控制**；**少记东西 → 记忆**；**前后统一 → 一致性**
- 易错：默认值/渐进揭示/真实世界隐喻属"减少记忆负担"，不是"控制之下"

**模块四要素（78）**：输入输出 + 处理功能 + 内部数据 + 程序代码
- 对外特性 = 接口 + 功能；内部特性 = 数据 + 代码
- 陷阱："数据格式"不是模块构成要素

**信息库 Repository（86）**：网络目录 + CASE 工具目录/百科全书 + 打印的文档 + 内联网网站接口
- 区别：存的是**开发文档资产**，不是业务运行数据（≠ 数据库/数据仓库）

**代码重用方式（87）**：算法 → 函数/子程序 → 类/对象 → 模块 → 构件
- 判据：能否作为独立逻辑/抽象单元被多次调用或嵌入
- 排除法：出现**变量/常量/文件/项目/属性/行为**即排除该选项

## 附录 B：主观题答题规范

> 源于 65 / 67 / 68 / 90 / 91 / 114 / 115 等案例与论文错题的共性失分

1. **条数 = 分值**：按分值确定答题条数，宁可多列一条要点。
2. **维度并列展开**：多角度归因（如"问题 + 改进"，"技术 + 管理 + 人员"）。
3. **先答问题，再答结论/改进**：勿只答改进不答问题，勿只分析不给结论。
4. **结合题干原词**：状态名、术语、限定词尽量用题干原话，勿自造名词。
5. **结合项目数据**：论文第 3 问必须落到本项目选型理由、使用方法与**量化效果**。
6. **理论↔实践一一对应**：模型/过程要列全、讲清技术特点，且前后不矛盾。
7. **注意字数上限**：案例小问常有硬性字数限制，需按点精简。
