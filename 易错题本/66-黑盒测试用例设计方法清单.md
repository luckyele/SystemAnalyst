
# 备考笔记：黑盒测试用例设计方法清单

## 一、题目

> 黑盒测试根据 SRS 所规定的功能来设计测试用例，一般包括功能分解、等价类划分、边界值分析、判定表、因果图、状态图、随机测试、错误推测和正交试验法等。

**答案：正确（√）**

解析：**黑盒测试（功能测试 / 基于规格说明的测试）**以**软件需求规格说明书（SRS）**所描述的功能为依据来设计测试用例，**不关心程序内部结构与实现**。题干列举的**九种方法**——功能分解、等价类划分、边界值分析、判定表、因果图、状态图、随机测试、错误推测、正交试验法——**均属黑盒测试用例设计方法**，与教材口径一致，故该说法**正确**。

- 判据只有一条：**"是否只依据功能/规格说明（输入→输出），而不看内部代码"**。九种方法全部只看输入输出与功能描述，故全部成立。
- 常见误读：把"状态图""随机测试""功能分解"误当作白盒或非测试方法。事实上它们是**基于功能行为**设计的黑盒方法，与白盒的"语句/分支/路径覆盖"无关。

## 二、知识点：黑盒测试用例设计方法清单

### 1. 核心原理

黑盒测试**不打开"盒子"**，只把被测对象当作一个**输入 → 输出**的黑箱，依据 **SRS（需求规格说明书）** 描述的功能来设计用例、验证功能是否达标。常用**九种**用例设计方法如下（题干完整清单）：

| 方法 | 核心思想 | 关键词锚点 |
| --- | --- | --- |
| **功能分解** | 把整体功能**逐层分解**为子功能，对各子功能分别设计用例 | 功能树、逐层细化 |
| **等价类划分** | 输入域分成**有效/无效等价类**，每类取一个代表值 | 分类、代表值、有效/无效 |
| **边界值分析** | 错误多发于**边界**，取边界值及其**越界邻近值** | 边界、越界、±1 |
| **判定表（决策表）** | 列出**条件桩/动作桩与全组合**，每列一条用例 | 条件桩、动作桩、组合列 |
| **因果图** | 用图形表达**输入条件与输出的因果关系及约束**，理清**输入组合** | 因果、输入组合、约束 |
| **状态图** | 按**状态迁移（事件→状态转移）**设计用例，覆盖合法/非法迁移 | 状态、迁移、事件 |
| **随机测试** | **随机**产生输入做测试，依赖大量随机样本暴露缺陷 | 随机、蒙特卡洛 |
| **错误推测** | 凭**经验直觉**推测可能出错之处，定向设计用例 | 经验、直觉 |
| **正交试验法** | 用**正交表**从海量组合中挑**少量均衡样本** | 正交表、成对组合 |

一句话判据：**黑盒看"做什么"（输入→输出），白盒看"怎么做"（语句/分支/路径）**。上述九法都只依赖功能/规格说明，故全部属黑盒。

### 2. 关键公式/规则

**（1）"九法"速记与归属**

| 类别 | 方法 | 说明 |
| --- | --- | --- |
| 基于**输入域** | 等价类划分、边界值分析 | 最基础，常配合使用 |
| 基于**逻辑/组合** | 判定表、因果图、正交试验法 | 处理多条件组合，控制用例规模 |
| 基于**行为/流程** | 功能分解、状态图 | 按功能层次或状态迁移设计 |
| 基于**经验/随机** | 错误推测、随机测试 | 补充性手段 |

**（2）两条易混关系**

| 关系 | 结论 |
| --- | --- |
| 因果图 → ？ | 转换为**判定表（决策表）**逐列生成用例 |
| 判定表列数 | $$2^n$$（$$n$$ 为条件数），因果图**约束**会删去不可能组合列 |

**（3）黑盒 vs 白盒方法对照**

| 维度 | 黑盒（本题九法） | 白盒（结构） |
| --- | --- | --- |
| 依据 | **SRS / 功能** | **程序内部逻辑 / 代码** |
| 看什么 | 输入 → 输出 | 语句、分支、路径、条件 |
| 代表方法 | 等价类、边界值、判定表、因果图、状态图、正交、错误推测、随机、功能分解 | 语句/判定/条件/路径覆盖 |
| 覆盖强度（白盒） | — | 语句 < 判定 < 条件 < 判定条件 < 条件组合 < 路径 |

### 3. 解题步骤

1. **判断题型**：本题是"**判断正误**"型，直接核对**方法归属**是否成立。
2. **抓判据**：黑盒测试的判据是"**是否只依据功能/规格说明、不看内部结构**"。
3. **逐法核对**：功能分解（按功能层次）✓、等价类划分 ✓、边界值分析 ✓、判定表 ✓、因果图 ✓、状态图（按行为迁移）✓、随机测试 ✓、错误推测 ✓、正交试验法 ✓ —— **九法全部落在黑盒一侧**。
4. **下结论**：题干表述**正确（√）**。

## 三、易错点

1. **误把"状态图""随机测试""功能分解"当成白盒或非测试方法**（本题主要陷阱）：三者都是**基于功能/行为**设计用例的**黑盒方法**，与内部代码无关。
2. **把"等价类划分"记成白盒**：等价类划分只看输入域与规格说明，是**黑盒**的当家方法（详见 [57-黑盒测试方法辨析-等价类划分边界值因果图与判定表.md](57-黑盒测试方法辨析-等价类划分边界值因果图与判定表.md)）。
3. **把"因果图"与"判定表"张冠李戴**：因果图理清逻辑后**转换为判定表**再逐列出用例；因果图本身的别称是**鱼刺图/石川图/鱼骨图**，不是转换目标。
4. **漏记方法名**：软考教材的**标准九法**要背全——**功能分解**与**状态图**最容易被漏，恰恰是本判断题的采分点。
5. **混淆测试方法维度**：白盒/黑盒是"**是否看内部结构**"的维度；静态/动态是"**是否运行程序**"的维度（详见 [53-软件测试-静态与动态测试辨析.md](53-软件测试-静态与动态测试辨析.md)）。黑盒方法**大多属动态测试**（要运行程序）。
6. **误以为黑盒只在系统/验收阶段用**：黑盒在**单元、集成、系统、验收**各阶段都能用，尤其在**系统测试与验收测试**中作用不可替代（可与 [52-软件测试-测试阶段目的与接口验证辨析.md](52-软件测试-测试阶段目的与接口验证辨析.md) 对照）。

## 四、扩展延伸

- **九法记忆口诀（按输入域→逻辑→行为→经验分组）**：
  - **输入域**：等价类划分、边界值分析；
  - **逻辑组合**：判定表、因果图、正交试验法；
  - **功能行为**：功能分解、状态图；
  - **经验随机**：错误推测、随机测试。
- **各种方法的"产物"**：等价类/边界值 → 代表性用例；因果图 → **判定表** → 用例；正交试验 → 正交表 → 代表性用例；状态图 → 状态迁移用例。
- **正交试验的价值**：判定表列数随条件数**指数爆炸**（$$2^n$$），正交表用**成对覆盖**把组合数从指数级压到可控规模，是"用最少用例覆盖最大风险"的典型。
- **与其它测试维度串联**：
  - 阶段维度（单元/集成/系统/验收）见 [52-软件测试-测试阶段目的与接口验证辨析.md](52-软件测试-测试阶段目的与接口验证辨析.md)；
  - 静态/动态维度见 [53-软件测试-静态与动态测试辨析.md](53-软件测试-静态与动态测试辨析.md)；
  - 黑盒方法辨析真题见 [57-黑盒测试方法辨析-等价类划分边界值因果图与判定表.md](57-黑盒测试方法辨析-等价类划分边界值因果图与判定表.md)。
- **现实类比**：把被测系统当作一台**自动售货机**——
  - **功能分解**＝先按"选货、付款、出货"把整机拆成子功能分别测；
  - **等价类划分**＝把投币金额分成"够/不够"两类各取一代表；
  - **边界值分析**＝专测"刚好够""差一分"；
  - **状态图**＝测"待机→选货→付款→出货"各状态迁移是否合法。
  全程**只按面板按键与出货结果**判断，**从不打开机箱看电路**——这就是黑盒。
