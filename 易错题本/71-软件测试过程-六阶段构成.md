
# 备考笔记：软件测试过程-六阶段构成

## 一、题目

> 软件测试过程包括：项目需求分析阶段、制订测试计划阶段、设计测试文档阶段、搭建测试环境阶段、执行测试阶段、缺陷管理几个阶段。（官方教材第二版 P509）

**答案：正确（√）**

解析：教材把**软件测试过程**定义为贯穿项目全过程的一组**有序活动**，并明确划分为**六个阶段（环节）**：**项目需求分析 → 制订测试计划 → 设计测试文档 → 搭建测试环境 → 执行测试 → 缺陷管理**。题干列举的六项与教材口径**完全一致**，故该说法**正确**。

- 判据只有一条：**测试是不是"只等于执行测试"**。答案是**否**——测试从**需求分析**就介入（测试左移），到**缺陷闭环**才结束。
- 常见误读：以为测试过程从"测试计划"或"执行测试"才开始。事实上**项目需求分析阶段**是六阶段的第一环，也是采分点。

## 二、知识点：软件测试过程-六阶段构成

### 1. 核心原理

**软件测试过程**不是一个孤立动作，而是**贯穿项目生命周期**的一组有序活动：从**需求分析**起步，经**计划、文档设计、环境搭建、测试执行**，最后以**缺陷管理**收口，形成"**认识需求 → 规划 → 备料 → 就绪 → 验证 → 闭环**"的完整链条。

| 阶段 | 主要工作 | 关键产出 / 关注点 |
| --- | --- | --- |
| **① 项目需求分析阶段** | 测试人员**参与需求分析**，理解并评审需求，识别**可测试性**与风险 | 需求评审意见、可测试性分析（**测试左移**起点） |
| **② 制订测试计划阶段** | 确定**测试范围、目标、策略、资源、进度、风险** | 《测试计划》：测什么、怎么测、谁来测、何时测 |
| **③ 设计测试文档阶段** | 设计**测试方案 / 测试说明 / 测试用例**等文档 | 测试用例、测试规程、测试文档（**用例设计**在此） |
| **④ 搭建测试环境阶段** | 准备**软硬件、网络、数据、测试工具**，尽量贴近生产 | 可用的测试环境 + 缺陷跟踪/自动化工具 |
| **⑤ 执行测试阶段** | 按计划**运行用例**，记录实际结果、上报缺陷、**回归** | 测试执行记录、缺陷单、测试报告 |
| **⑥ 缺陷管理阶段** | 缺陷的**记录、跟踪、修复验证、统计、闭环** | 缺陷报告、缺陷趋势统计（贯穿执行阶段） |

一句话记忆链：**需求 → 计划 → 文档 → 环境 → 执行 → 缺陷**。

### 2. 关键公式/规则

**（1）六阶段速记**

| 序号 | 阶段名（教材口径） | 助记 |
| --- | --- | --- |
| 1 | 项目**需求分析**阶段 | 测试提前介入（左移） |
| 2 | **制订测试计划**阶段 | 定范围/策略/进度 |
| 3 | 设计**测试文档**阶段 | 用例与方案成型 |
| 4 | **搭建测试环境**阶段 | 软硬网络数据工具 |
| 5 | **执行测试**阶段 | 跑用例、报缺陷 |
| 6 | **缺陷管理**阶段 | 跟踪到闭环 |

**（2）三个易混维度（务必区分）**

| 维度 | 含义 | 举例 |
| --- | --- | --- |
| **测试过程（活动流程）** | 测试**怎么走**的六个环节 | 需求分析→计划→文档→环境→执行→缺陷管理 |
| **测试阶段/级别（被测范围层次）** | 测**谁**、在哪一层 | 单元 → 集成 → 系统 → 验收 |
| **测试类型/方法** | 用**什么手段**测 | 黑盒/白盒、静态/动态、功能/性能测试 |

### 3. 解题步骤

1. **判断题型**：本题是教材**原文陈述**（判断正误 / 填空型），直接核对**阶段名称与顺序**。
2. **抓标准口径**：教材（第二版 P509）明确为**六阶段**——需求分析、测试计划、测试文档、测试环境、测试执行、缺陷管理。
3. **逐项核对**：题干六项与教材**一一对应、无缺漏、无杜撰**（如未混入"测试报告编写""测试评估"等非教材阶段名）。
4. **下结论**：题干表述**正确（√）**。

## 三、易错点

1. **漏掉"项目需求分析阶段"**（本题最大陷阱）：测试**从需求分析就介入**，不是从"测试计划"或"执行测试"才开始，这是**测试左移**的体现。
2. **把"缺陷管理"当成测试过程之外的活动**：它是六阶段中的**最后一环**，且**贯穿执行阶段**——执行测试时同步记录/跟踪缺陷，直至**修复验证闭环**。
3. **混淆"测试过程"与"测试阶段/级别"**：过程是**活动流程**（六环节）；级别是**被测层次**（单元/集成/系统/验收），二者是**不同维度**（对照 [52-软件测试-测试阶段目的与接口验证辨析.md](52-软件测试-测试阶段目的与接口验证辨析.md)）。
4. **把"设计测试文档"窄化为"设计测试用例"**：教材用"**测试文档**"，范围更宽（含测试方案、测试说明、用例、报告等），用例设计只是其中一部分。
5. **搞错"搭建测试环境"的位置**：环境搭建在**设计与计划之后、执行之前**，不是最先也不是最后一步。
6. **漏记或杜撰阶段名**：只背"计划—执行"两段，或自行添加"测试评估""测试报告"等**非教材阶段名**，都会判错。

## 四、扩展延伸

- **与 V / W 模型的对应**：六阶段中的"需求分析"对应 V 模型**左侧**的测试介入点（需求↔验收测试、概要设计↔系统测试、详细设计↔集成测试、编码↔单元测试），"执行测试"对应**右侧**的验证活动。
- **测试左移（Shift Left）**：把测试活动**前移到需求分析与设计阶段**（阶段①），尽早发现缺陷、降低修复成本——正是"需求分析阶段"被列为六阶段之首的原因。
- **缺陷生命周期（闭环）**：新建 → 分派 → 修复 → 验证 → 关闭（/重开），对应阶段⑥缺陷管理的核心流程。
- **与其它测试维度的串联**：
  - 测试阶段/级别见 [52-软件测试-测试阶段目的与接口验证辨析.md](52-软件测试-测试阶段目的与接口验证辨析.md)；
  - 静态/动态维度见 [53-软件测试-静态与动态测试辨析.md](53-软件测试-静态与动态测试辨析.md)；
  - 黑盒方法清单见 [66-黑盒测试用例设计方法清单.md](66-黑盒测试用例设计方法清单.md)；
  - 系统测试与性能测试论文要点见 [67-系统测试与性能测试-论文写作要点.md](67-系统测试与性能测试-论文写作要点.md)；
  - 第三方测试与覆盖准则见 [68-第三方测试-测试环境与MC-DC覆盖准则.md](68-第三方测试-测试环境与MC-DC覆盖准则.md)。
- **现实类比**：把软件测试过程比作**做一场大考准备**——
  - ① 需求分析＝**看清考试大纲**（考什么）；
  - ② 制订计划＝**排复习计划**（怎么分配时间）；
  - ③ 设计文档＝**编习题与错题本**（出题）；
  - ④ 搭建环境＝**备好考场与文具**（备料）；
  - ⑤ 执行测试＝**正式答题**（考试）；
  - ⑥ 缺陷管理＝**批改订正直到全会**（闭环）。
  光"答题"（阶段⑤）远不等于整个备考过程——这正是本题要澄清的误解。
