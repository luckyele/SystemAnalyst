# 项目事实基础资料模板

> 用途：把"一个真实项目"拆成可复用的事实元件，供四道论题（分布式 / 数据平台 / AIOps / 需求分析）切换主线时反复调用。
> 原则：**只写能自证的事实**。写不出的格子留空并标 `待补`，不要用行业常见值填满——阅卷追问一句"当时怎么定位的"就会露。
> 用法：A、B 填一次，C、D 每周补 2 张卡，E 随卡同步登记。

---

## D. 故障 / 问题事件卡（第三段"问题与解决"的唯一来源）

> 备考目标：备 5 张。**这一节编不出来，是论文"空"的根本原因。**

### 事件 D-__　一句话标题：__________

| 字段 | 填写 |
|---|---|
| 发生时间 | 年月日（可只到月，但要统一） |
| 触发条件 | 大促 / 扩容 / 机房断网 / 版本发布 |
| 现象（带数字） | 例：某分片 CPU 90%，下单 P99 从 300ms 升至 1.8s |
| 影响范围 | 影响多少用户 / 多少订单 / 持续多久 |
| 定位过程 | 先看什么指标 → 排除什么 → 锁定什么（**这是最能体现真实感的一段**） |
| 根因 | 一句话，技术性，不写"经验不足" |
| 临时措施 | 止血手段 |
| 根本措施 | 改造内容 |
| 结果 | 指标回落到多少 |
| 沉淀 | 是否形成预案 / 监控项 / 规范 |
| 可挂靠的论文题 | □分布式 □数据平台 □AIOps □需求分析 |

**备选事件清单（按论题）**

| 论题 | 优先准备的故障类型 |
|---|---|
| 分布式 | 数据倾斜、脑裂双写、跨分片查询慢、消息重复消费 |
| 数据平台 | 数据口径不一致、任务链雪崩、小文件过多、实时链路延迟 |
| AIOps | 告警风暴、误报率高、根因定位慢、监控盲区 |
| 需求分析 | 需求频繁变更、干系人冲突、需求与实现偏差 |
