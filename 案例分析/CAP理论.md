## CAP 理论
CAP 理论是分布式系统领域的一个基本结论。它描述了分布式数据存储在三个性质之间的取舍关系。三个性质分别是：一致性、可用性和分区容忍性。
### 三个性质
**一致性（Consistency）**
一致性指：所有结点在同一时刻看到的数据相同。具体表现为：任一读操作，无论发到哪个结点，都返回最近一次写入的值。若系统中存在一个结点返回旧数据，另一个结点返回新数据，则系统不满足一致性。
**可用性（Availability）**
可用性指：系统收到的每个请求都能得到响应。响应不需要是最新的数据，但必须是成功的、非错误的返回。若某个结点收到请求后拒绝服务或长时间无响应，则系统不满足可用性。
**分区容忍性（Partition Tolerance）**
分区容忍性指：当网络发生分区，即结点之间的通信中断，形成互相隔离的组时，系统仍能继续工作。网络分区无法避免，因为网络本身不可靠。因此，对于跨网络的分布式系统，分区容忍性通常被看作必选项，不能放弃。
### 核心结论
CAP 理论的核心结论是：在发生网络分区时，系统不能同时完全满足一致性和可用性。必须在两者之间做出选择。
原因如下。设网络分为两个隔离的组，A 组和 B 组。客户端向 A 组写入新值。此时 A 组和 B 组无法通信，B 组不知道新值。客户端随后向 B 组发起读请求。此时 B 组面临两个选择：
1. 拒绝该读请求。这保证了一致性，因为系统不会返回旧值，但牺牲了可用性。
2. 返回旧值。这保证了可用性，因为请求得到了响应，但牺牲了一致性。
无论选哪个，一致性或可用性必失其一。此即 CAP 理论的核心内容。注意：此矛盾只在分区发生时出现。网络正常时，一致性和可用性可以同时满足。
### 实践中的取舍
实践中的系统通常按以下三类设计。
**CP 系统**
CP 系统在分区发生时选择一致性，放弃可用性。分区期间，多数派之外或无法参与协调的结点会拒绝服务。分区恢复后，系统重新同步数据，恢复一致状态。适合对数据正确性要求高的场合，如金融账户、库存扣减、分布式锁服务。典型系统如 ZooKeeper、etcd、HBase 的协调层。
**AP 系统**
AP 系统在分区发生时选择可用性，放弃一致性。分区期间，每个结点继续接受读写，各自维护本地的数据版本。分区恢复后，系统执行冲突消解，把分叉的数据合并为一致版本。合并策略可自定义，如取最新时间戳、按业务规则裁决。适合对响应速度要求高、能容忍临时旧数据的场合，如购物车、评论、点赞计数。典型系统如 Cassandra、DynamoDB、CouchDB。
**CA 系统**
CA 系统不存在于跨网络部署的分布式环境中。理由：网络分区必然发生，分区容忍性不可放弃。CA 性质的组合只对单机系统或同一网络内的严格协调系统成立。因此，实践中不存在真正的分布式 CA 系统。某些资料把传统单机数据库归为 CA，这只在该数据库不跨网络部署时成立。
### 与 BASE 的关系
BASE 是与 CAP 相关的一组工程实践原则。BASE 指基本可用、软状态、最终一致性。它是对 AP 路线的具体化：系统在分区时保持可服务，允许数据处于临时的中间状态，分区恢复后数据逐步收敛到一致。多数互联网大规模系统采用 BASE 风格，配合异步复制、多版本存储、冲突合并等机制实现。
### 常见误解
- 认为 CAP 是三选二，即任选两个性质。此理解不完整。分区容忍性是前提，不是可选项。真正的选择只发生在一致性与可用性之间，且只在分区发生时。
- 认为选择 AP 意味着永久放弃一致性。AP 只是分区期间的临时行为。分区恢复后，系统仍可通过同步协议收敛到一致状态。
- 认为一致性和可用性是二元的全有或全无。实际系统常在两者之间做程度调节。例如，限制拒绝服务的结点范围，或缩短返回旧数据的时间窗口。
- 认为强一致性和可用性绝对互斥。例如，Quorum 机制要求读写多数派交集，在多数派可通信时，既能保证一致性，又能提供服务。此设计在分区发生且多数派不可用时，牺牲部分可用性。
- 混淆 CAP 中的一致性与 ACID 中的 C。ACID 的 C 指事务前后数据满足业务约束，CAP 的 C 指多副本读到的数据相同。两者是不同的概念。
### 设计影响
CAP 理论对分布式系统设计给出直接指导：
- 部署跨网络的系统，先确认分区容忍性为默认前提，再在一致性与可用性之间定位需求。
- 对正确性敏感的数据路径，采用 CP 路线，配合共识协议，如 Raft 或 Paxos。
- 对体验敏感的数据路径，采用 AP 路线，配合最终一致性机制，并明确旧数据可被容忍的窗口。
- 同一系统内可以分模块取舍。例如，订单支付模块用 CP，商品浏览模块用 AP。不必对整个系统做统一选择。
- 评估方案时，问两个问题：分区期间，拒绝多少请求？分区恢复后，需要多久收敛到一致？答案决定取舍是否合理。
### 小结
CAP 理论的要点有三：网络分区不可避免，因此分区容忍性是前提；分区发生时，一致性与可用性不可兼得，必选其一；正常无分区时，两者可同时满足。工程上的意义不在于证明矛盾，而在于给出取舍框架：按数据性质分区处理，敏感数据选一致性，体验数据选可用性，并设计好分区恢复后的收敛机制。
